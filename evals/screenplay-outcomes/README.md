# 剧本结果验收

目的：检验用户能否拿到可继续编辑的完整剧本，而不是证明脚本能运行。单元测试不能替代本验收；一次开发者辅助试跑也不能证明陌生用户独立成功或长剧质量稳定。

后续自主优化见 [迭代协议](autonomous-loop.md) 与 [独立比较和定向修补记录](iteration-2026-09-22.md)。以下“本轮”规格及自评步骤保留为初次试跑记录，不替代后续的评审来源说明。

防同质化方法另有 [行为回归用例](diversity-regression.md) 与 [接入及维护者自查](diversity-run-2026-09-22.md)。它们检查换皮、审美分歧、未知事实、阅读泄漏与探索状态，不用极小合成样本宣称真人创作验收。

## 本轮用例（写作前固定）

- 基线：drama-studio `e7e543e`，0.2.0。
- 入口：用已分发的安装器在隔离项目目录安装技能，读取安装后的方法，使用该副本中的工具。
- 制作条件：现代现实题材、六集闭合故事、每集以 90—120 秒为创作目标、四名有台词角色、两个室内场地、不靠群演／异能／隐藏富豪身份解决冲突。实际时长待围读，不能用字数换算宣称达标。
- 用户输入未指定具体题材，本轮由测试操作者选择，不能记为用户已确认。
- 参考：实时查询 mali-story 已有官方模板，记录资料质量和缺项。模板存在不代表已证实为近期爆款。
- 执行者：当前 Codex 会话，同时是本项目开发者；结果存在作者介入与自评偏差，非陌生用户盲测。
- 不改写现有用户项目、不付费分析、不创建远端正式采用记录。创作产物留在 git 忽略的 `projects/outcome-eval-20260922/`。

## 验收依据

2026-09-22 用户已明确选择验收目标：**编剧可接手修改的完整初稿**。这一确认只确定交付成熟度；当前六集稿的具体质量与采用仍待评审。

初稿合格的含义：约定范围内正文完整、主线及结局成立、人物关键行为有动机、跨集不存在需要推翻主线才能解决的矛盾；编剧能保留主体结构，围绕节奏、场面和台词继续修改。允许局部不足，但要定位并交代影响。若需重设核心人物目标、重建主要因果链或重写结局，则本轮不满足“可接手初稿”，不能以文件完整抵消。

O4 在初稿阶段要求显式制作条件得到尊重、专业不确定项已列明；真实样衣验证、精确拍摄预算与送审材料不作为本阶段必交项。它们若暴露核心情节无法成立，仍需回到故事层面修正。单集时长目标继续保留，当前围读未测状态也保留。

| ID | 用户结果 | 必须看到的证据 | 不能冒充的替代指标 |
| --- | --- | --- | --- |
| O1 | 拿到完整、可编辑稿 | 六集完整正文、结局、版本和阅读入口 | 文件存在、字数达标 |
| O2 | 能顺着故事读下去 | 每集人物行动改变处境，下一集承接后果；关键反转有前置依据 | 说话人轮数、问号数量 |
| O3 | 能看懂人物为什么这样做 | 对立人物有具体利益；主角至少一次选择带来真实代价 | 人物小传字段齐全 |
| O4 | 制片能开始拆解 | 角色／场地／关键道具清单与正文一致；高成本镜头和专业工艺疑问显式列出 | 场标题数、地点标签数 |
| O5 | 是独立故事 | 对标的具体人物、关系、指纹桥段与转折链逐项比较 | 低字面重合率 |
| O6 | 能处理修改意见 | 保留初稿、明确反馈来源、修改对照、上游与后续影响复核 | 覆盖文件后说已修好 |
| O7 | 能继续工作 | 当前版本、未解决问题、下一动作清楚；新会话只凭交接包恢复 | 原作者依靠聊天记忆继续 |
| O8 | 编剧认为可接手 | 编剧对具体版本选择“可继续打磨／需结构重做／不可用”，并指出需返工内容 | 模型给自己的高分 |

分层判定：产物存在由程序核对；叙事与制作问题需引用集／场／台词；编剧采用必须由真实人完成。未做人审的输出只能是待审稿，不能给出总体验收通过率。

## 测试过程

1. 固定用例与要求，记录版本、输入和初始假设。
2. 完成参考筛选、原创选题、设定和全剧集纲。测试操作者选题只能记录为测试决策。
3. 按安装技能完成六集初稿，并保存原始版本。
4. 执行语义自评；逐项引用正文。反馈若来自模型，标为“模拟编辑反馈”，不得伪称编剧反馈。
5. 保存修订版与差异，重查连续性、人物与制作条件；不能悄悄换验收目标。
6. 交付编剧可打开的完整包，并保留待人审结论。
7. 下一轮由未参与开发的编剧在新会话执行；记录人为提示次数、结构返工、是否能继续修改，而非只问满意度。

不同题材的多次独立试跑与 60—80 集压力测试另行记录；此六集用例不覆盖下载、收费拉片、新用户 OAuth 或其他宿主导入。
