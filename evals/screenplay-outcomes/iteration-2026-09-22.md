# 自主创作迭代：一次真实候选比较

此记录延续 [六集试跑](run-2026-09-22.md)，按 [本轮协议](autonomous-loop.md) 执行。用户目标是编剧可接手修改的完整初稿，并授权自行测试、修订与优化。此处只记录可公开的方法与结论；私人正文和参考资料未进入分发包。

## 过程与证据

保持同一六集闭合故事、四名有台词角色、两个室内场地与现实题材。保留 v2 基线，先提出三种改写方向，选择重新安排人物自主选择与后段取舍的一种，写完整 v3。中性代号 lake=v2、pine=v3，映射及 SHA-256 在本地留存。

- 独立编剧评审先读 pine，再读 lake；独立观众／制片视角评审顺序相反。两个评审上下文不参与写作、不读版本映射或其他意见。
- 两位评审都认为两稿可保留主体继续编辑，都偏好 pine，同时指出它的退步。属于同模型家族的不同上下文，不是跨模型或真人盲测；交换顺序不能消除所有偏差。
- 连续性评审另读全文，区分已证实、被原文反驳与未知。发现最终正式缝制状态不够明确，未将未知工艺断言为不可能。
- 一轮定向修补形成 v4。编辑和连续性评审复核全文：可继续编辑；交付状态缺口已补；未检出新增的已证实致命矛盾。复审知道前轮内容，不能称为重新冷读。

## 本轮看到了哪些收益

| 目的 | 基线与候选差异 | 证据判断 |
| --- | --- | --- |
| 保住下限 | 正式缝合、清理珠针与疏缝、检查、交还后试穿被明确写出；旧款、新修改费用和客户尾款分开 | 独立连续性复核确认文本状态缺口已补；实际工艺与耗时仍未知 |
| 提升人物选择 | 旧款从末集结清改为第3集结清，主角有自由离开后决定留下 | 两位模型评审认为选择与代价更强；不能推出真实观众更爱看 |
| 提升后段冲突 | 第一轮方案失败后必须放弃前文珍惜的外观，不只是再修一次 | 两位评审认为后段出现新的有效取舍 |
| 兑现关系变化 | 助理敢指出主角仍托着衣服；主角撤手接受失败，结尾鼓励更早指出问题 | 关系变化通过动作发生，并在结尾回收 |
| 防止新版退步 | v3 的巧合证据、过快让步、重复阻拦被指出；v4 改为误读与口头指示冲突、付款条件与变更追认 | 定向编辑复核认为主要问题解决；尾声仍可压缩，有两处局部表达待打磨 |

结论是这一次内部创作比较产生了具体收益，而非已测出系统下限、上限或成功概率。基线本已达到模型判断的初稿下限，不能伪造“从不可用到可用”的改善。

## 评审校准与产物核验

另给连续性评审两个小片段：一个有照片可用、原件被带走；另一个明确唯一原件未归还却在主角口袋出现。评审正确区分两者，未将使用照片误报为原件矛盾。仅两个合成片段，不报告通用检出率或误报率。

最终 v4 保存六集全文、当前设定与集纲、角色／道具／钱款／知识状态、差异与逐版评审。本地文件入口为 `projects/outcome-eval-20260922/story/deliveries/README.md`；该目录被 Git 忽略，不是公开仓库下载内容。版本、客观检查、报告与文件摘要同存于本地 `iteration-02/reviews/`。

冻结安装副本的工具用于显式地点约束和参考摘要字面重合统计；不以工具退出成功宣布叙事质量通过。六集、四名说话角色、两个地点与结局另外按正文核对。90—120秒/集是待围读目标；没有实际服装试制、真实编剧采用或市场留存数据。

## 写回产品

新增技能内的 [自主创作迭代方法](../../skills/drama-studio/references/creative-loop.md)：保留基线、先试结构路线、分开下限与上限、独立比较、反证核查、定向修补与停止条件。写作说明修正为按已有授权采纳经核实意见，不再要求用户批准每条内部改稿建议。采用和对外发布继续按用户既有策略记录。

本轮 Python 3.10 的30项测试通过，仓库静态检查通过。首次误用系统 Python 3.9.6 时，三项分发测试因低于明确的最低版本而失败；改用支持版本后通过，没有改低最低版本或跳过用例。

交接包另经另一模型上下文恢复检查，当前版本、集纲、状态表及入口链接一致；该评审者曾读旧基线，不是陌生用户独立试用。
