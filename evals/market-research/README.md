# 可选榜单接入的行为验收

目标是验证AI能用现有资料形成可追溯候选并交接拉片，而不是仅验证Markdown能加载。本目录全部作品、ID、指标和模板均为虚构夹具，不是真实榜单、剧本、原片或服务回执。

## 用例与判读

| 用例 | 提供的原始资料 | 需要观察的行为 |
| --- | --- | --- |
| partial | 三行榜单、缺四天的窗口、间隔三天的变化、三份简介、同名模板列表 | 识别导出日与榜单日差异；不报日增或连续七天；按两人两室约束淘汰巨兽群战；模板身份和已分析范围保持待核对，ID不混用 |
| summary-only | 只有研究摘要、多标签同一作品示例、available=false | 继续有限研究；不把示例还原成全榜、编造简介或凑三部；不以标签占比证明饱和度、题材因果或收益；服务不可用不等于空榜 |
| confirmed-opening | 用户已确认同作品，81集源剧与5集模板详情，仅研究开篇 | 沿用选择与匹配，继续已有资料的开篇研究；分别记录源剧总集数和已分析范围；检查字段存在不冒充原片真实性，不要求新增收费拉片 |

`partial` 是保留上游字段形状的人工裁剪资料，包括缩小为前三名的观察窗口，不是实际采集器的逐字导出。`profiles.json` 和 `templates.json` 是测试提供的资料列表，不是本项目新增的统一导出协议。`research-latest.json` 的正式上游结构区别见[接入说明](../../skills/drama-studio/references/hongguo-rank.md)。

## 复跑方法

为每个用例建立独立临时目录：将当前 `skills/drama-studio/` 完整复制到 `skill/`，将对应 `fixtures/<case>/` 复制到 `inputs/`。新会话只接收技能和原始输入，不给本文件、预期答案、旧报告或其他用例。发送：

> 使用本目录skill/SKILL.md完成inputs/request.txt的任务，结果保存在本目录。不要修改输入或技能。

保存真实会话事件、技能快照、输出及输入哈希；通读实际报告并按表核对事实、反证、下一动作和没有做的操作。不要仅凭退出码、字段名或关键词出现判行为通过。模型、同账号配置和提示范围均须记录，不能把禁读提示称为OS隔离。

## 2026-09-23执行

三个fresh Codex CLI会话均完成，关闭memories且不resume；共用本机账号和宿主配置，没有指定其他模型。每个会话仅收到技能快照、原始资料和请求，未提供本页预期答案。维护者通读报告和事件：

- partial：将09-23导出与09-20榜单分开，保留缺四天与最长可确认两天，正确使用三天间隔；淘汰巨兽群战作为低成本制作对标，将两份同名模板保持待匹配。
- summary-only：仅列一部有证据的候选，识别摘要非全榜和服务不可用；没有补造简介、持续性或第二／第三部作品。报告额外给出明确标为虚构假设的开发方向，不计作市场证据或正式选题。
- confirmed-opening：沿用用户确认的身份与开篇范围，实际执行reference-check按5集检查；保留passed为null，指出正文重复、不能支持真实开篇机制判断，交付研究与交接卡，没有将81／5差异当作重做全剧拉片的理由。

三例均未出现本表针对的误判，输入和技能文件哈希未改变。这是维护者判读的小样本文件入口测试，不是实机MCP或用户成功率。真实日志和完整报告归档到本地被忽略的 `projects/market-integration-eval-20260923/`，不随技能分发。

## 工程与未覆盖项

核心运行时未新增依赖、采集器或远程服务。原有36项标准库测试、技能结构检查、相对链接、临时项目安装及两个宿主ZIP用于验证分发；它们不证明宿主导入或市场推荐效果。

本轮不安装上游服务、不复制活动数据库、不变更定时任务，不运行真实收费分析。已配置MCP的线上数据新鲜度、真实业务调用、不同宿主实机使用和编剧的实际选择仍需独立验证；合成材料判断正确不能替代这些结论。
