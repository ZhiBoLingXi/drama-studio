# 接续、版本与交付

## 本地与远端

本地工作目录包含 `research/`、`reference/`、`planning/`、`episodes/`、`reviews/`、`deliveries/`。`.drama/project.json` 只是绑定与进度提示，`PROJECT.md` 是可读摘要。初始工具不会创建远端项目，也不会证明数据已同步。

正文和记录保存完整文本，注明输入版本／摘要、产物状态和远端回执。项目目录不可放在技能安装目录中。凭据、临时签名 URL 不写入可分享交付包。

自主开发另保留 `planning/development-rNN.md` 及 `planning/experiments/` 中的探索片段；阅读记录放 `reviews/`。由 AI 按 [创作开发](development-lab.md) 按需建立文件，不修改用户已有记录。`PROJECT.md` 指向当前完整稿、当前探索、输入版本、保护的创作选择、未核实材料与下一动作。安装本身不生成这些创作记录。

## 恢复顺序

1. 读取本地绑定和上一轮回执；如果远端 projectId 已存在就读取该项目，不重建同名项目。
2. 发现当前工具，刷新远端任务、Brief、候选与采用版本。远端不可读时只报告缓存状态及其日期。
3. 检查是否有响应未知的提交、尚未同步的本地稿、外部编辑或过期检查。
   同时核对保底稿与探索片段，恢复评审实际看过的内容及阅读测试进行到哪一步。已见结局的上下文不能继续冒充首次预测；需要重测时换未看过的上下文，否则标记事后自评。
4. 指明下一动作和所需输入，继续独立且已获授权的工作。进度依赖聊天记录时先补证据，不能猜造 ID。

源码或说明中出现候选工具，不代表当前服务部署了它。专业保存／采用能力缺失时保留本地草稿，不以通用写块接口绕过。正式事实来自已采用正文；未经采用的候选不更新正式连续性。

宿主切换先停止原宿主写入，再移交同一工作目录和项目 ID。本版本没有多宿主写锁或事务性本地版本库，只支持串行接续。不要声称具备并发安全或自动跨设备同步。

## 交付

接续前核对正文、集纲、报告中的输入摘要和当前磁盘内容。摘要不同可能是编剧的新修改，不自动恢复旧文件；保留两者，说明冲突，在新版本处理。模拟反馈注明测试来源。删角色／缩场地时，检查其原有信息、行动、交易和情绪功能，不能只删台词或用电话声、旁白偷增演员。明确保留的编剧句子与结局选择单独复核。

跨批次先保存从正文恢复的入口状态，再写后续：谁已知何事、已完成和未完成的付款／承诺、物件所在、当前故事日。集纲是计划，事实来自当前有效正文；不得假定未写出的集纲事件已发生。检查批次边界和结尾回收，集纲不能替代完整正文。

按用户选定版本生成：市场与对标依据、参考资料索引、人物设定、蓝图与集纲、N 集完整正文、检查报告、问题清单、修订对照。核对集数唯一且连续、结局存在、没有占位文本；未完成报告不得写“全部通过”。

提供下限、辨识度、阅读偏好三个独立结论，并标明模型／真人及阅读范围。探索候选和被放弃方案保留供接续，但与完整正文入口分开；没有真人读者不填留存率、追剧率或采用率。

交稿前按 [结果验收](delivery-readiness.md) 核对实际正文，而非只清点文件；提供编剧明确可打开的阅读入口和待反馈问题。制作拆解列出道具不同状态与替身需求，不以单一物件名称低估不可逆操作的成本。

默认可交 Markdown。DOCX、飞书只在当前环境有实际可用导出工具／连接器时使用，不通过改扩展名冒充格式转换。飞书交付读实际导入结果并核对文档；正文修改前先获取当前修订，防止覆盖编剧新稿。没有飞书不会阻塞本地交稿。

用户尚未审阅时标“待确认评审稿”。样稿、候选完整、模型评审通过、用户采用和整剧验收是不同状态。每次交付附实际产物位置、远端 ID／版本、待办与下一动作。

发现版本摘要不同时，先盘点目录内的历史副本、外部编辑稿和回执；“未读取旧副本”不能写成“没有旧副本”。交付报告中的缺失声明也要查证。

合并分批正文时，批次封面和状态说明放到交付入口，不插在上一集场景中。保留冻结源文件，单独生成合并稿及映射／差异；补动作标记等机械规范化要列清楚，不能当作剧情提质。约束检查因格式无法核验时，修复新交付副本后重跑，不通过放宽规则消除警告。
