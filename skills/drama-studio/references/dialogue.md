# 台词：像这个人说的话

[工位通用协议](workstations/README.md) · [单集工位流程](writing.md#工位流程)

模型写中文台词，默认会滑向书面腔：省主语、对仗、像格言，只交代信息不带态度。只加禁令没有用，它会换一种书面腔。能把台词拉回口语的是正例：这个人物、这种方言、对这个对象说话的正例。本文件规定正例怎么存、怎么进包、哪一遍专门改台词、谁来听。

## 1. 口语和书面腔差在哪

下面的例子都是为说明而编的，不出自任何剧本。

| 看什么 | 书面腔 | 像人说的 |
| --- | --- | --- |
| 对谁说 | 没有称呼，像对空气说 | 先叫人：“二叔，你听我说” |
| 句子 | 省主语、两句对仗：“先救人，再算账。” | 完整，可以啰嗦一点：“人先弄出来行不行？账回头我跟你算！” |
| 态度 | 冷静陈述事实 | 带着得意、嘴硬、心虚或不耐烦 |
| 用词 | “此事”“兽口”“无妨” | 具体的、当地的说法 |
| 一句话干什么 | 塞信息 | 表态度，信息顺带出来 |
| 语气词和重复 | 没有 | “嘛”“呗”“可”“这有啥”，该重复就重复 |

不是每个人都话多、都带口头禅。少话、直说、端着说的人物照样成立，前提是声音卡里这么写了。

## 2. 声音卡（K5）

C2 写人物小传时，每个主要人物同时写一张声音卡，是小传的一部分，随送审包一起给主创，不单独审核。主创对台词提了意见，先出声音卡的新修订，再改正文。

声音卡是一张 `knowledge-card`，放在项目 `knowledge/cards/<cardId>@r<n>.json`：

| 字段 | 写什么 |
| --- | --- |
| `knowledgeType` | `K5` |
| `processing` | `curated`（写出即可装包） |
| `evidence` | `nature: creative_hypothesis`；`sources` 指向人物小传的文件或页面和版本 |
| `content.problem` | “<人物名>怎么说话”。**人物名必须和正文里的说话人写法一致**，关口靠它对上人 |
| `content.situation` | 对谁、什么场合：对家里人、对上级、对对手各怎么变 |
| `content.mechanismOrFact` | 称呼别人的习惯、口头禅和大致频率、句子长短、方言和年代用词、态度倾向（爱吹、嘴硬、先损后帮） |
| `content.examples` | 5–10 句例句，写明是对谁说的 |
| `content.counterExamples` | 这个人不会这么说的句子 |
| `content.failureConditions` | 学过头的样子：句句带口头禅、方言堆成漫画腔 |
| `limits` | `unverified` 写“未经主创单独审核”；`judgedBy` 写“AI 起草，随人物小传 vN” |

一张卡可以写一个人，也可以写说话方式相近的一组人，但每个人的名字都要出现在卡里。方言、年代的通用说法另写一张 K5 卡。

## 3. 对照卡（K9）

主创给出“原句 → 改句”时，每一组都存成对照卡并用上，这是目前唯一的人工标注。`knowledgeType: K9`，`evidence.nature: source_statement`，`sources` 写主创原话的日期和出处；`content.examples` 写“原句 → 改句”，`content.mechanismOrFact` 写差在哪，`content.situation` 写是哪个人物对谁说的。私有剧本的句子只留在项目里，不进技能包。

## 4. 进包

- 作者包（`--role author`）：本集出场、有台词的人物的声音卡必须装进去；相关的对照卡按人物取。
- 知识分区不超过包的四分之一，超了就少装对照卡，不截正文。
- 例句是让人学说法的，不照抄句子，也不为了用上例句加戏。

## 5. 台词遍

C5 写完场面稿之后，单独做一遍只改台词的运行：

1. 装 `--role dialogue_author` 包：本集场面稿、出场人物的声音卡、对照卡、入口状态记录。不装集纲以外的新材料。
2. 逐句过：这句是谁对谁说的，想要什么，带什么态度；用声音卡里这个人的说法重说一遍。念出来拗口的改掉。
3. **只改台词行**（“人物：话”和它的括注）。场头、动作、说明一个字不动；要动就回到场面稿去改，不在这一遍里改。
4. 篇幅装不下时不压台词：提 C4 变更（拆集或减事件）。
5. 写 `run-handoff`，产出是台词遍之后的稿；保存和回执照常。

## 6. 台词读

台词遍之后，在没看过集纲和作者说明的新上下文里做一次台词读（`--role dialogue_read` 包，只放正文，可带前一集）：

- 逐句标出“不像这个人会说的”，写明原因并给一个改法。
- 盖住名字猜是谁说的：随机抽几句只看话，猜不出是谁，说明人物声音没分开。
- 标出学过头的：口头禅太密、方言成了漫画腔。
- 记成 `review-record`（问题归 C5），和首读、次读的问题一起进那一次定向修订，不增加修订轮数。

宿主能用另一个模型家族做台词读时优先用，并在记录里写明；同一模型家族的新上下文也可以，但 `claimsIndependence` 仍为 false。

## 7. 关口

`drama_tools.py season-check <项目> --episodes <起-止>` 默认核对三条：

| 规则 | 查什么 |
| --- | --- |
| `voice-card` | 最终稿里台词达到 3 句的每个说话人，名字出现在作者包装入的某张 K5 卡里 |
| `dialogue-pass` | 作者运行之后有一次 `dialogue_author` 运行，包里有 K5 卡，且前后两稿除台词行外逐行相同 |
| `dialogue-read` | 台词遍之后有一次装了本集正文的 `dialogue_read` 运行 |

脚本认“人物：话”这种行为台词行（名字不超过 10 个字，可带括注）。它只查这些记录在不在、对不对得上，判断不了台词自不自然；台词好不好由主创看稿决定。确实不需要这三条时加 `--skip-dialogue`，输出里会记 `dialogueChecked: false`，交付说明里写明原因。
