# 首次初始化、修改设置与状态检查

用户安装后、要求“初始化工作室”“修改采集时间”“关闭自动更新”或“检查配置”时使用。本模块由宿主 AI 引导，配置与验证记录保存在用户工作目录；不引入新的模型服务或后台守护进程。安装技能不等于同意联网采集、注册定时任务、上传或收费。

## 先检查，再问缺少的选择

只读检查当前宿主的文件／执行／调度能力、Python、现有技能与连接，以及用户指定工作目录。新对话只在当前工作区及已知入口查找 `STUDIO.md`；找不到时询问记录位置，不假定从未初始化。若有历史初始化记录，先读记录再查实际状态，保留原选择；只读相关配置字段，不读取或输出令牌。不要为发现配置扫描全部私人文档。

查找已有红果部署和采集任务时，以用户提供的位置、当前宿主任务列表及配置为起点。记录能查到的范围；没有某宿主的任务查看权限，不等于整台电脑没有任务。已有部署优先复用，目录未知就保留缺口，不另起一套库。

把问题合并为少量用户能决定的选项；已有明确答案不重问：

1. **工作目录**：展示一个技能目录之外的建议位置，沿用用户指定位置。没有文件权限时提供可下载的配置记录，不假装写到了用户电脑。
2. **榜单更新**：“暂不开启／需要时手动采集／定时采集”。选择定时后才问频率、当地时间与时区，例如“每天 10:00，Asia/Shanghai”；可同时询问这次是否立即采集一次。不开启时不再追问时间。
3. **可跳过的常用偏好**：真人／漫剧、常写类型和受众、通常集数／单集时长、制作约束与交付格式。允许“每个项目再定”，不替用户默认 12 集或 60 集。

选择采集后补充范围：“仅榜单／榜单及作品资料”。仅榜单是较轻的起点；作品资料的每次上限必须展示并记录。用户未选定范围、频率、时间或时区时，计划保持待配置，不自行开启。用户只给时间并不构成开启授权。

账号登录、云端保存、飞书交付、视频下载等只在选用该能力时补问；不把可选模块未配置判为整个安装失败。

## 初始化项目与默认行为

| 项目 | 初始化内容 | 未选择时的行为 |
| --- | --- | --- |
| 环境与宿主 | 安装位置、版本／内容摘要、命令／文件／调度能力 | 不猜测桌面或后台权限 |
| 文件与数据 | 工作目录、项目目录、素材位置、红果已有部署及实际数据库位置 | 项目不放技能目录；不迁移、清库或开启云同步 |
| 数据入口 | 本地脚本／已有 MCP／导出文件／暂不配置 | 有本地执行能力可直接用脚本；MCP 不是采集前置 |
| 更新安排 | 手动／定时、采集范围、频率、时间、IANA 时区、立即采集选择 | 定时关闭；立即采集未授权；不追补虚构历史 |
| mali-story | 现有服务、宿主连接名、OAuth、只读模板验证；个人／团队空间（有实际支持时） | 可稍后连接；安装不创建远端项目或改变账号范围 |
| 下载与上传 | 手动路径或现有夸克能力、素材目录、上传选择 | 手动接续；不试下载整剧、不自动上传 |
| 创作习惯 | 常用类型、受众、制作条件、篇幅偏好 | 未知保持空；项目指示优先，固定两次审批流程 |
| 交付 | 本地 Markdown；可选 DOCX／飞书及真实目标 | 本地文件；不新建共享文档或公开链接 |
| 费用 | 外部付费功能是否启用、按任务授权的额度／币种／单位与范围 | 付费功能关闭；预算配置不等于某次任务获批 |
| 数据维护 | 历史、原始页面、日志、备份与故障提示方式 | 保留数据，不自动删除；状态页提示失败，不向他人发消息 |

工作室偏好仅作为新项目起点。项目总集数、选题及送审审批仍按 [两次审批](approval-flow.md) 保存到各自项目；不能用工作室初始化一次性批准未来作品。

## 预览具体变更后应用

用 [初始化记录模板](../templates/initialization-record.md) 准备可核对预览：复用什么、将新增／修改什么、写入位置、数据与任务归属、首次是否运行、计划时区及下次执行时间、资源和费用、关闭方法、未支持项。

用户已明确授权的相同范围无需重复确认。含糊的“安装好了就行”或未回复，不能视为同意可选采集／调度。用户已经给出“每天北京时间10点采集，仅榜单，现在先跑一次”时，完成环境核验和预览后可以按这一范围继续，不再要求相同批准。

按依赖分别执行并验收：工作目录与记录 → 所选数据入口／连接 → 获授权的首次采集 → 所选调度 → 读取回执。首次采集不是开启未来定时的隐含权限；用户只授权未来计划时跳过首次采集。不存在可用调度能力时保存待配置计划并给手动入口，不假装已启用。

记录分两部分：**用户想要的配置**与**实际验证状态**。启用意愿、调度器创建成功、未来会触发、真实采集成功是不同结论。工具超时或返回不明时先按任务 ID／唯一标识查询，禁止盲目重建。

## 红果直接脚本入口

先核对部署的 README、版本和实际 `--help`。当前核对的上游是 macOS／Linux 方案，使用 curl、Python 与独立依赖环境；采集脚本包含 `fcntl`，不能把 Windows 原生运行算作已支持。其他环境需要实际可用的兼容执行环境，否则使用导出或已有服务。

以下相对文件名只用于识别现有部署命令，执行时用已验证的解释器及脚本绝对路径，工作目录设为该部署目录，不能直接在技能目录运行：

| 目的 | 上游已存在的命令 |
| --- | --- |
| 榜单状态／最新内容 | `hongguo.py status` / `hongguo.py latest --rank comic --limit 20` |
| 仅采集榜单并导出 | `hongguo.py collect` |
| 榜单加作品资料 | `research.py daily --limit N`，N 是用户选定并经当前版本核验的资料上限 |
| 资料状态／资料卡 | `research.py status` / `research.py profile --series-id ID` |

这些命令无需启动 `server.py`。只有用户需要宿主工具接口时才配置 MCP；其他查询与数据口径见 [红果接入](hongguo-rank.md)。首次使用没有数据库时，状态失败是“尚无数据”，不是先装 MCP 就能解决。

当前上游 CLI 的数据库固定为部署目录下 `data/rankings.sqlite3`，导出在 `reports/`；没有可直接使用的 `--data-dir`。复用该实际路径，不承诺工作目录配置能移动数据库。`hongguo.py collect` 更新全部四类榜单，`--rank` 不限制采集范围；`daily --limit N` 限制作品资料采集，不限制榜单行数。研究偏好过滤在查询阶段执行。

新部署需单独选择持久位置并核对源版本、依赖及可用环境；不复制私人数据库或其他机器虚拟环境。未部署时保留这一缺口，不能只写脚本路径就宣布可用。

## 定时任务的运行约定

- 优先复用现有同库任务。已存在的任务不因技能升级重新创建或变成另一个时间；改时间前核对所有者与用户授权。跨宿主看不到既有任务时保持待核实，不能据此创建第二个写者。
- 优先调度固定的采集命令，不用定时模型会话完成纯采集。只有宿主确实支持 AI 自动化且用户接受其额度消耗时才选该方式；不要求用户提供模型 Key。
- 执行器须支持所选时区，或经过验证的时区转换／DST 策略。展示实际下次运行的当地时间和 UTC 时间；不能保证时区语义就不登记为已启用。不静默改成机器时区。
- 记录实际执行机器、账号／任务作用域、解释器、工作目录、脚本版本、同库唯一标识和任务 ID；定时任务不能引用临时测试目录、聊天沙箱或容易被升级替换的技能目录。
- 同一库串行采集。上游目前对榜单、详情分别加锁，不能据此宣称整个 `daily` 全程互斥；所选调度／执行层必须防止整条更新重入，不能核实则暂不开启定时，保留手动入口。
- 错过执行时建议恢复后只采当前数据一次；不以重放过去日期伪造历史。是否能补跑由实际执行器决定并记录；关机、休眠或应用退出条件必须告知，不承诺始终在线。
- 每次记录开始／结束、退出状态、榜单成功时间、资料成功／失败数量、数据日期及报告位置。详情部分失败时记“部分成功”，旧可用数据继续保留；非零退出码不能抹掉榜单已成功的事实。
- 初始不做自动重试风暴、不清空库、不回退付费来源；失败保留证据，先查原因。自动清理与通知他人均需单独选择和明确范围。

上述是选择执行器的验收条件，不代表本技能附带通用调度器。当前安装脚本只安装文件，未实现 cron／launchd／Windows 任务的自动注册、跨机器锁或事务性配置；以可用宿主能力实际完成的步骤为准。

## 配置保存、修改与验收

在用户选定的工作室根目录保存 `STUDIO.md`（按模板填写），项目保存在其 `projects/` 或已有目录；不要放进分发包。同名文件若不是本工作室初始化记录，保留原文件并另存有明确名称的新记录，返回实际入口；多个工作室分别维护，不互相覆盖。机器路径、连接别名和任务 ID 是当前宿主的绑定，不自动复制到新机器执行。无本地持久化能力时交付该记录供用户保存，并标“未在本机持久化”。

记录带修订号、观察时间、输入版本和用户原话。修改前读现有记录，更新前再比较读入的内容；变化则保留冲突版本并重新核对，不覆盖新修改。当前仅支持单写者串行配置，不声称具备跨进程原子比较交换。

重新配置只处理用户指定项：先比较计划与实际任务，再修改自己管理或用户明确授权的绑定任务，读回验证后更新记录。暂停／删除任务不删库，卸载技能不自动删除工作室和采集部署；关闭结果必须由调度器读回确认。停止未来触发与取消正在运行的一次任务分别报告。

验收分别给出：技能安装、配置保存、宿主发现、账号授权、真实业务读取、采集结果、调度登记、真实定时触发、创作验收。尚未到下一次执行时，只能说“已登记，定时触发待验证”。可选项使用“未开启／跳过／不支持／待用户登录／待配置／部分成功／已验证”，不汇总成含糊的“全部成功”。
