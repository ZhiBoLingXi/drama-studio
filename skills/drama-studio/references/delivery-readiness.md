# 以编剧可接手为目标的交稿检查

先明确本次要的是方向样稿、完整初稿、制作稿还是送审稿。用户未指定时可先按“编剧可继续修改的初稿”推进并注明假设，不默认承诺可直接拍摄或上线。

## 针对实际稿件核对

| 问题 | 应提供的证据 |
| --- | --- |
| 用户能拿到完整内容吗？ | 本次约定的完整集数、具体阅读入口、版本、结局或样稿截断位置；没有“略”“待补”冒充正文 |
| 故事能接起来吗？ | 每集主角行动、代价与后果；下集承接；反转依据的前置位置。用集／场／台词定位，不用钩子数量作证明 |
| 人物行为可信么？ | 主角和对立者在关键选择时具体想保住什么、怕失去什么；不能靠配角突然降智或改性格换过关 |
| 制作人员能开始拆解吗？ | 从正文提取角色、场地、时间、关键道具与变化状态；明确专业工艺和不可逆操作的验证需求。两个场地标签并不证明低成本 |
| 与对标足够独立吗？ | 抽象情绪机制和可识别表达分开；具体关系、动作道具组合、转折链逐项比较；字面率只作为辅助 |
| 完整之外是否有辨识度？ | 单列换皮风险、可预测但无新发现的段落、人物是否只服务主题，以及本剧不可替代的选择与场面；“比旧版好”不能代替此判断 |
| 修改真正生效了吗？ | 原版本、反馈来源、修改位置、影响集数、修订后复核。模型自评要标明，不能伪称编剧反馈 |
| 用户能接着改吗？ | 当前有效版本、未决问题、下一动作；用户修订优先，过期检查不能继续当新版本证据 |

发现可能影响故事成立的问题时，优先修因果与动机，再润色台词。不要为过检填字、切场，或通过改验收规格隐藏失败。按用户授权修订，超出范围的结构改变先形成可审阅方案。

## 判断与交付

将三个结果分开：客观规格核对、引用正文的编辑评审、真实编剧采用。模型既写又审时明确其偏差；没有外部审阅不能声称独立评审通过。

用户已授权自行优化时，先按 [自主创作迭代](creative-loop.md) 完成内部生成、比较和修补，再交付最佳候选；“待人审”不能成为停止已授权内部改稿的理由。独立模型上下文、不同模型和真实编剧意见分别标明。

交付可编辑正文、设定与当前集纲、制作拆解起点、已修问题与未决项。让编剧针对具体版本选择“可继续打磨”“需要结构重做”或“不可用”，并给出位置。未收到回答保持待审，不自动填写采纳率、人工节省时间或满意度。

下限成立、辨识度结论和阅读偏好分别交付。按 [阅读记录模板](../templates/reading-record.md) 区分预测与揭示后反馈：已读全文的评审不能回填首次预测；实际读到哪一段就只报告该范围。真实读者对“猜到但仍期待”和“意外却不可信”的区别，比单一新颖分更有用。无真人数据可继续模型筛查，但不得代造真人回答。

单集时长要通过实际围读／剪辑验证；模型估算和字数换算不能冒充实测。长篇稳定性、多题材泛化、陌生用户独立完成及市场表现都需要另外的证据，一部短样稿不能证明整套产品已验收。
