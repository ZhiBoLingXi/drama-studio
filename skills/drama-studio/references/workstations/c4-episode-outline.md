# C4 分集集纲

[工位通用协议](README.md) · 契约 v0.1

| 项 | 内容 |
| --- | --- |
| 必读本剧依据 | 全剧结构、前集实际正文（不是前集计划）、邻集接口、人物近期经历 |
| 主要知识 | K3、K4、K8、K9 修改经验；没有知识缺口时可以不检索 |
| 产出 | 可写的分集纲：处境、行动目标、阻力、关键选择、关系变化、情绪变化依据、出口与待核前提（kind：`episode_outline`） |
| 交接 | `run-handoff`；问题属于上游时提 `changeProposals`（目标层须在本层之前） |

## 方法要点

- 情绪变化必须有可写的选择与经历；“被感动、决定原谅”不能留给正文补黑箱。
- 入口读取前集实际发生的事；前集未写完时用显式计划接口并标“待正文对齐”。
- 核对单集事件数与字数规格：一集装不下这些事时拆集或减事件，不留给正文去压台词。
- 按戏剧问题检索，不按“找一场精彩的戏”检索；检查连续几集是否用同一种解法。

## 整季集纲怎么写

写送审用的完整集纲（如第 11–60 集）也走工位，不能只把节拍表分给几个子代理并行扩写。

1. **先有上游，各自留交接**：C2 人物小传与规则、C3 全剧结构各写一份 `run-handoff`，产出存成页面（`characters`、`outline` 等语义）。本次新写的就如实写成新写，只有用户给定的材料才写“采用用户给定”。
2. **按顺序分段**：一段默认不超过 15 集，一段一个 C4 运行，前一段写完、存好，再给下一段装包。不并行：并行的几段互相看不到，同一件道具、同一条关系会被写成两种说法。
3. **每段的集纲包**（`context-pack --role author`）至少装四样：C2 最新产出的人物小传与规则、C3 最新产出的全剧结构、前一集集纲的最新稿、已写正文的出口状态 `runs/state/after-ep-<已写到的集>.md`。已经有正文时，后面的集纲从实际正文接，所以送审包的顺序是：前 10 集集纲 → 前 10 集正文 → 第 11 集起的集纲。对标、拉片资料和知识卡按需要装，装了就写清用途。
4. **集纲也要审**：每段写完，由没写这段集纲的上下文（子代理、新会话或真人）审一次，记 `review-record`，`target`／`additionalTargets` 指向各集集纲。重点看：每集有没有主角的关键选择，相邻集钩子有没有因果承接，前文审读里指出的集纲层问题（如对手为剧情变蠢、钩子被下一集放掉）在后面的集纲里有没有重犯。
5. **存成页面**：每集集纲一个 `episode_outline` 页面（带 `episode_ref`），记回执。
6. **关口**：`drama_tools.py season-check <项目> --outline <起-止>` 逐集核对上面五条，不通过不能写“集纲已按流程完成”。

集纲文件名带 `outline` 和集号（如 `runs/plan/outline-011.md`），`season-check` 靠它认出是哪一集的集纲。

## 停止与边界

不设每场反转配额；每场能说明它承担什么变化即可。 返修次数不超过 `task.revisionBudget`；触顶就交付未达标候选并写明瓶颈。
