# Drama Studio：分层 Harness 与知识库实施路线

日期：2026-09-29。版本 v1.1。状态：实施建议，未启动实现、正式立项或发布。

本路线把[知识库与六工位设计](drama-studio-knowledge-harness-design-2026-09-29.md)和[既有 R0–R7 任务包](../refactor-stages-2026-09-28/README.md)合成按价值交付的批次。不是另起一套独立进度表，也不把此前计划任务追认成已完成。

**v1.1 修订（对齐[系统架构 v1.1](drama-studio-system-architecture-2026-09-29.md)）**

- D0–D5 是唯一的阶段编号；R0–R7 只作工程任务 ID，知识设计 §11 的 A–D 已被取代（架构 §3.1）。
- 已确认没有长期离线用户。候选、修订与采用只存 mali-story；本地不实现快照版本库、CAS 或幂等，只做知识卡、ContextSnapshot、选材记录和临时断线草稿（架构 §10.3）。
- 首版知识只做项目私有，共享范围推到 D4 之后（架构 §8.5）；K1–K9 的扩大生产以 D2 对照结果为门槛（架构 §15.1）。
- 每批验收只能引用 S（脚本强制）或 R（服务端强制）项，M（模型约定）项按审读抽查报告（架构 §4.1）。
- D0 契约以 JSON Schema＋正反测试交付；每批按架构 §15.2 报告实际消耗。

## 1. 推进原则

先用小型、真实可用的知识和模块跑通“集纲如何变成更好的正文”，再扩展为完整创作链，最后解决长篇规模与团队采用。mali-story 是候选与采用的唯一存储，因此联网从 D0 起就是前提，不是最后一步。

三个工作方向贯穿全过程：

- **创作方法**：每层作什么决定，输入如何支持决定，输出怎样交给下层。
- **知识生产**：材料从哪里来，怎样变成有条件的可用知识，如何避免模板化。
- **可靠执行**：版本、来源、权限、恢复、候选与正式状态分离。

三个方向应尽早汇合。不能先做完庞大的工作流平台再找创作价值，也不能用几次优质手工改稿宣称软件已实现。

最小可靠执行从首批就要有，而且主要靠复用：版本、冲突与幂等由 mali-story 服务端保证（R 项），本地脚本只保证装包、引用与用途过滤（S 项）。延后的只是复杂自动化、规模化和共享知识，不是版本、权限、采用边界。

## 3. 六个交付批次

```text
D0 契约 Schema、基线与线上能力发现
          ↓
D1 远端候选适配 ＋ 本地选材装包 ＋ 项目私有种子知识
          ↓
D2 C4 集纲 → C5 正文 → C6 审读的实际闭环
          ↓
D3 补齐 C1 定位 → C2 人物世界 → C3 结构
          ↓
D4 长篇连续创作、受控并行与知识复用
          ↓
D5 可安装交付／按能力联网／有条件制作试点
```

这是优先交付顺序。测试材料准备、知识整理和工位设计可提前进行；不意味着所有任务只能串行。远端适配不再等到 D5：D0 做只读发现，D1 在获准测试项目上接通候选保存与回读。

### D0：冻结最小契约与第一批问题

目的：让不同模块、不同 session 真正能交接，而不是各自解释“人物卡”“知识卡”“已完成”。

工作：

1. 固定两仓库及已安装技能的实际基线、保护文件、素材权限；保存本轮测试之外仍缺少的证据。
2. **线上能力发现（只读）**：经 MCP 确认候选保存、回读、列举、快照读取和采用接口实际可用的形态、鉴权与测试项目授权。源码存在不算可用；发现结果决定 D1 适配范围。
3. 定义最小公共对象为 JSON Schema：任务、知识卡（项目私有）、ContextSnapshot、选材记录、审读记录、运行交接、远端回执映射。候选与修订直接引用 mali-story 的既有对象，不在本地另定义。
4. 为 C1–C6 各写一份薄工位契约，作为 Schema 的字段约束＋一段方法说明，放入技能的 `references/`，不另起设计文档。
5. 为每条首轮不变量标注 S／R／M 层级（架构 §4.1）；验收条件只写 S、R 项。
6. 冻结首轮目标：人物行动、对白语感、情绪承接、集纲因果、结构重复；明确旧稿要保护的价值。
7. 划分开发样例、回归样例和保留题。私有剧本不进公开包，43–44 集仅作为已见回归。

交付：`tests/` 中的 Schema 正反用例（纳入 `unittest discover`）、六份薄工位契约、能力发现回执、来源与权限清单、基线回执、首轮验收说明。

进入 D1 的条件：Schema 测试通过；每个对象有生产者与消费者；事实、计划、候选、采用能被明确区分；线上候选保存／回读在获准测试项目上确认可用，或已记录不可用并停在 D0。没有必要冻结所有未来功能。

### D1：做出最小“知识到上下文”的可运行路径

目的：给定某一集和任务，系统能够准确取出需要的本剧资料与有用知识，形成可检查的工作包。

工程工作：

- **远端适配（R 项）**：候选保存、全文回读、列举与版本读取走 mali-story；记录请求身份与回执映射，响应丢失先按原请求身份查询再决定是否重试。本地不实现版本库、CAS、幂等或写者竞争处理。
- **本地装包（S 项）**：知识卡、原始证据和用途分别保存在项目工作目录；支持字段／关键词定位、精确原文展开、来源去重与用途过滤。
- 由宿主提出选材，工具按引用组装包；工具不假装已经理解语义，不增加模型运行时。
- 必需本剧事实按远端确切版本加载；可选知识不能挤掉必要原文。超量、错版、来源缺失、无权限均显式报告。
- ContextSnapshot 与选材记录写入后不再修改，附哈希清单；同一输入可复现装包结果，但不承诺模型生成完全可复现。
- 临时断线草稿：仅保存文件与所依据的远端版本号，恢复连接后作为新候选提交，由服务端判冲突。

知识工作：

- 先围绕首轮问题生产小型、项目私有的种子集，覆盖生活／行为、叙事机制、表达样本、结构比较及改稿反例；数量由首轮问题决定，不为覆盖面凑卡。
- 每条记录原始证据、条件、局限、允许用途；没有外部证据的合成样例标为合成，不伪造采访或成功案例。
- 人物语感优先整理本剧原场面，暂不建设可套用金句库。

交付：候选在测试项目上保存→回读→列举的往返证据；能定位、展开、组装的本地装包工具；一组项目私有知识卡；C4/C5/C6 的示范工作包。

进入 D2 的条件：候选往返与断线对账有实测证据（R）；错版和跨用途引用被装包工具拒绝（S）；必需材料缺失不会伪装齐全；新会话能从远端候选和本地快照知道用了哪些材料；选入知识能说明服务哪个决定。这里还不能声称提高了创作质量。

### D2：交付第一个有创作价值的版本

目的：不再只测试“上下文写得好不好”，而是实际看到更可写的集纲、更贴人物的正文，以及没有被掩盖的新问题。

以已有上游材料作为输入，保留它们真实的候选／确认状态；不因为试点需要就伪造 C1–C3 已获采用。

实现路径：

1. C4 从已选方向、人物与结构材料、前文事实中，产出本集目标、阻力、选择、变化和跨集接口。
2. C5 按集纲及本剧原场面组织上下文，写完整正文。允许局部探索，涉及上游决定则回传变更提议。
3. C6 先读正文，再看作者说明；分别检查事实、明确创作目标和开放偏好。
4. 问题路由到真正负责的层：台词实现回 C5，关键选择缺失回 C4，人物或主线前提有问题则标记 C2/C3 的待修，而不是不断润色正文。
5. 默认只进行一个候选加一次定向修补；停留问题与损失可见，不用无限循环把分数刷高。
6. 集纲、正文及修订作为 mali-story 候选保存；实际输入（ContextSnapshot）、审读、新旧对照和下一集实际要接的后果留在本地运行记录并引用远端候选 ID。

评估采用分步归因：先验证流程可跑，再比较“本剧分层上下文”和“在同等上下文上加入精选知识”的结果；需要时另保留现行方法对照。不是每次做全因子大实验，也不把所有变量一起改变后的收益都归给知识库。

**知识投入门槛**（架构 §15.1）：只有对照显示本剧上下文的收益已到顶、剩余缺口确属材料或方法缺失时，D3/D4 才扩大 K1–K9 生产；否则先改选材规则和工位方法。门槛结论写入 D2 报告。

> **D2 门槛结论（2026-10-06，单次结果，主创已认可）：不扩大。** 见 [D2 知识增益评估与门槛结论](../d2/knowledge-gate-report.md)。

每次运行按架构 §15.2 记录调用次数、字数与人工等待；宿主给出真实用量时才记具体 token 与费用。

交付给用户的是：旧稿／集纲问题 → 新集纲 → 完整新正文 → 知识改变了哪些决定 → 收益、损失及未决项。技术日志作附件，不让用户先读日志才能判断戏。

进入后续阶段分两条：

- 工程链路可靠、语义结果不足：可以继续完善不依赖质量结论的工具，但方法保持实验状态，回到具体问题。
- 实际正文出现有依据的收益，且关键代价可接受：扩大试点的题型与模块，不自动采用或扩写整季。

没有真人评价时只能得到模型／编辑层面的结果，不能称语感已获用户认可。

### D3：补齐从素材到故事的上游能力

目的：系统不仅能改善已有稿，也能产生不只是换皮的新故事。上游契约在 D0 已设计，此时完成实际生产与验证。

- C1：用现实张力、类型需求和已读对照，产出因果真正不同的选题候选；仍保留选题选择边界。
- C2：将方向转成人物欲望、关系策略、规则与代价，写声音探针；探针不自动成为正史。
- C3：将这些人物放进持续产生后果的因果主线，形成段落、人物弧与承诺回收，再交 C4。
- 按 D2 门槛结论决定是否扩充上游需要的生活、职业、文化、类型与完整作品知识；仍为项目私有，不把正文用知识原样复制给上游。
- 建立结构比较：去掉姓名与题材术语后，比较利益关系、关键选择、解法和代价。

交付：一套由知识支持、各层有产物与交接的创作包，并能向下写成实际场面。不以“结构图漂亮”“候选标题不同”作为完成。

通过条件：特色素材确实改变选择和后果；下层能够消费上层产物；遇到上层缺陷能回到正确层修改。新剧两个创作审批点不变，内部工位不新增六次人审。

### D4：验证长篇、跨集修订与受控并行

目的：从少量场面的成功走向持续创作，解决累积偏差和自我重复。

- 连续性同时记录事实、人物所知、关系变化、未兑承诺和情绪余波，且可以回读原文。
- 每个批次整合实际正文，不仅整合集纲。计划出口与实际出口不同必须传播给依赖方。
- 前文变化后，确定依赖失效；语义影响不明就标待核并扩大阅读，不声称依赖图能捕获所有文学联系。
- 按依赖安排任务：独立候选／独立段落可并行，强依赖部分局部串行；同一远端版本基线，不互相读取未交接的候选。并行写入冲突由 mali-story 的版本比较拒绝，本地只报告与重新读取。
- 同一主线跟踪反复使用的解法，区别有意回环、递进和机械重复。
- 知识反馈先进入待整理区；审读、项目采用、真实制作反馈分别记录，禁止自评自动晋升。
- 知识版本更正或权限变化，能定位受影响的 ContextSnapshot 和派生条目。
- **共享知识决策点**：若 D2/D3 证据支持，此时再设计工作室共享范围的所有者、授权与撤回的服务端落点；否则继续只做项目私有。

交付：跨多个叙事段落的连续产物及修订演练；保留故障、局限和不同判断。

通过条件：换会话、修改上游、候选冲突、来源撤回、并行汇合等情况不污染项目事实；创作没有明显退化成重复解法。局部测试仍不等于全季或商业验证。

### D5：分开软件交付、联网能力与制作采用

三种发布分别判断：

1. **软件交付**：完整回归、安装、旧本地项目导入 mali-story 的预览与明确 apply、保留用户改动、回退；只有公开可分发材料入包。
2. **其余联网能力**：候选读写已在 D1 接通；此处补审查任务、文档导出等剩余能力的发现与验证。断线草稿不冒充远端状态；未知调用先对账，不能盲目重做付费任务。
3. **真实创作／制作采用**：用户判断语感，导演在真实条件下检查交接、拆镜、片长与成本。没有反馈时保持未采用候选，已知独立工程工作可继续。

不重建项目权威数据库；正式项目和采用仍由 Mali Story 管理。跨请求持久状态不得藏在某个 API 进程内。涉及服务端数据库变更仍使用项目迁移、snapshot 和 journal。

## 4. 与旧任务的合并方式

R0–R7 继续表示工程责任，不再被理解为必须按整阶段瀑布式完成的唯一顺序。D0–D5 只表示演示／交付批次，不建立另一套任务完成状态。

| 交付批次 | 主要复用的旧任务 | 需要增加或扩展的内容 |
| --- | --- | --- |
| D0 | R0、R1-01/02/04、R1-07（改为 JSON Schema＋测试）、R5-01 | 六工位薄契约、知识来源／权限、知识卡与选材记录、S／R／M 层级标注 |
| D1 | R2-01（仅快照与知识文件）、R2-02（收窄）、R5-02、R5-03、R5-04、R3-01～03 的必要部分 | 知识定位与展开、来源谱系、用途隔离、知识与本剧记忆合包 |
| D2 | R2-06、R2-08（候选来自远端测试项目）、R3-04～06、R4 对应任务 | C4 集纲工位、C5/C6 联动、跨层返修、知识增益归因与投入门槛 |

## 5. 实现位置与技术边界

以下路径是拟议目标；不是已存在的文件或可执行命令。

```text
drama-studio/skills/drama-studio/
  references/workstations/       C1–C6 方法与选材规则
  templates/workstations/        必要输入、产物与交接模板
  schemas/                       D0 公共对象的 JSON Schema
  scripts/knowledge/             卡片、来源、用途过滤、定位与展开
  scripts/context/               确定性组装、引用和容量检查、快照哈希清单

drama-studio/tests/              Schema 与工具的正反用例
drama-studio/evals/              原创或获授权的开发／保留用例

项目工作目录（仅项目私有）
  原始材料、知识卡、ContextSnapshot、选材记录、审读、远端回执映射、断线草稿

mali-story（经 MCP）
  候选、修订、采用决定、快照来源
```

- 不建 `scripts/workflow/` 本地版本库；候选的保存、修订、冲突与恢复都走 mali-story。
- 上述模块可按真实规模合并，不为目录数量造组件。Python 工具继续只用标准库；不新增模型执行器或供应商凭据。`schemas/` 为 `.json` 文件，需同步放宽 `validate.py` 的随包文件类型检查。
- 模型负责语义选材、创作和审读；确定性工具负责引用、用途范围、组装和证据保留。模型无法读取的材料不算已核实。
- 首版不强制向量库或知识图谱；先用精确引用、字段、关键词和人工／宿主选材定位瓶颈。
- 首版不做跨项目共享知识；D4 决策点之前不把私有知识塞进一个假项目来绕过现有项目权限。
- Mali Story 优先复用 WritingContextService、CreativeContextService、StoryArtifactService 的已有职责。缺口先提出窄接口变更与消费方测试，不将客户端需要的所有工作流重新搬回服务端。
- 本地只保存执行证据，不拥有候选版本库，也不拥有第二套正式采用权威。

## 6. 每批同时回答四个验收问题

| 验收面 | 需要证明什么 | 不能代替什么 |
| --- | --- | --- |
| 工程可靠性 | 版本正确、来源可追、权限／范围受控、恢复不丢状态；只引用 S／R 项证据 | 不能证明戏好看；M 项只能报抽查结果 |
| 知识可用性 | 资料真实有边界、检索解决具体缺口、无答案泄露 | 不能由卡片数量或召回数证明 |
| 创作效果 | 具体行动、对白、因果和差异的变化；同时看损失 | 不能由检查通过或作者自评证明 |
| 人的采用／制作 | 对指定版本和范围的实际判断、实际制作证据 | 不能由模型偏好、上传成功或测试通过替代 |

工程证据满足后可以交付实验性能力；创作证据不足必须如实标注并限制提质声明。真人反馈缺失不应阻止所有工程开发，也不能通过更改状态名跳过真人采用。

试验控制：固定任务、可知模型条件和输入版本，保留所有尝试；先记录正文反应再披露作者说明。按预算逐步增加题型和重复，不把单次胜出说成稳定优势。旧 R4 的较大矩阵保留为扩展方案，不作为第一天必须支付的任务量。

## 7. 独立 session 的交接方式

获准执行后，每个 session 只接收负责范围的任务包，不复制全部历史聊天。任务包至少包含：

1. 目标与非目标、明确的改动文件／目录归属。
2. 输入产物的确切版本、必读原文及允许的知识范围。
3. 本工位契约和相关技能；不是所有工位的全部指令。
4. 可变空间、前后接口、未知与保护项。
5. 输出路径、候选状态、验收方式和停止条件。
6. 实际执行记录、未完成项与下一接手动作。

独立 session 不代表天然质量更高。多个 session 共用不可变输入，产物分别保存；协调者核对接口和实际正文后整合。工程人员在共享仓库中不得回退他人的改动，发生重叠先处理责任和版本。

创作并行按因果依赖，不按集号平均分包。上游尚未确认的选择可探索，但下游结果也必须保留对应候选身份。
