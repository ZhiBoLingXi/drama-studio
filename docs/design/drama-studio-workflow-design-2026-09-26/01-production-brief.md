# Establish explicit production conditions before drafting

M1 · 制作条件与约束 · 设计状态：红队修订 v2；待真实试点，未实现完整模块。

## English Summary

Capture production facts, preferences, unknowns and frozen material before they become invisible writing assumptions. Missing information limits production claims, not all authorized creative exploration.

## Problem

编剧拿到“低成本、能拍”的要求，却不知道演员、场地和特殊镜头的实际条件；导演直到拆镜时才发现一场戏虽然只有一个场景标题，却包含群演、形态变化、破坏状态和复杂动作。

本次救援稿没有实际资产、报价、粗剪与工时记录。现有 episode-check 接受显式数值规格，但不会验证来源是否获批准，也不理解物理场地和镜头难度。因此缺的不是默认增加“每集几场”，而是让条件的来源、强度与未知可见。

模块拥有：项目制作前提及约束版本。模块不拥有：因果判断、完整分镜、资金授权或最终放行。

## Requirements

### 1. 用户如何使用

1. 用户说“沿用前 20 集资产，后面改低成本”，看到系统从已有资料提取的条件，而不是空表。
2. AI 区分用户原话、资产清单事实、推测与待问项，给出影响最大的少量问题。
3. 用户补充能确认的信息；未答项继续保留未知，不被转换成默认预算。
4. 编剧看到“必须守住、优先争取、尚待核实”三组条件以及影响范围。
5. 正文出现与条件冲突的场面时，得到替代方案及损失说明；导演后续提供实测，形成新版本。

价值是让“暂不知道”成为可管理的风险，而不是让编剧替制片编造制作事实。

### 2. 方案取舍

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 使用全剧统一字数/场数门槛 | 检查简单 | 与题材、镜头成本、时长不等价 | 不采用为默认 |
| 所有项目必须先填完整制片表 | 条件全面 | 早期探索被预算细节阻断，用户负担大 | 仅制作筹备时深化 |
| 分层 Brief：关键已知先确认，其余按风险补齐 | 保留探索，逐步形成可靠边界 | 必须精确标示未知和影响动作 | 推荐 |

P0：已有材料提取、约束分类、来源与范围、冻结说明、未知清单、冲突提示、版本交接。P1：团队资产类别库、实际估算偏差回流。不包含自动报价或采购。

### 3. 输入与输出契约

输入：用户当前任务及原话；已有 STUDIO 偏好；制作 Brief；资产和粗搭清单；已知冻结段；当前正文快照。文件缺失必须显式记录，不能凭同名剧推定为实际制作版本。

输出 `production_brief`，使用公共产物头；每条条件至少包括：

| 字段 | 含义及约束 |
| --- | --- |
| `condition_id` | 稳定标识，同一条件改值创建新修订而非换名隐藏变化 |
| `category` | 片长、演员、场地、道具、特殊效果、预算、工期、冻结内容等；可扩展 |
| `statement` / `value` / `unit` | 人可读要求及可计算值；没有实际数值时 value 为空，不填 0 |
| `strength` | hard / preference / informational；只有有授权来源的要求才能是 hard |
| `knowledge` | confirmed / estimated / unknown / disputed，与强度独立 |
| `scope` | 集数、场、资产或整季；避免一条局部限制错误影响全剧 |
| `source_ref` / `confirmed_by` | 来源版本、位置、原话及有权确认该事项的人；AI 整理者不等于确认者 |
| `estimate_basis` | 估算方法、区间、假设、日期；仅估算项需要 |
| `enforcement_scope` | drafting / editorial_delivery / production_release，可多选且说明理由 |
| `verification_need` | 后续用什么证明，例如演员实读、具体镜头试制 |

资源类条件还需区分容量与承诺：`resource_id`、单位、占用时间窗、总可用容量、已消耗、已承诺未执行、本次需求、证据有效期/撤回状态与确认人。可复用资产以可用权利和版本表达，不强制像人力一样做数值扣减。动态资源在每次新放行和实际开工前复核；未知有效期不能被文件 hash 未变掩盖。

同一资源、同一时间窗内，已消耗、有效预约与本次新增需求不得重复计数或漏算。整周容量与剩余容量必须注明口径；采用剩余容量时不得再次扣历史消耗。预约用稳定 ID 去重，取消后明确释放；探索性试制也计入占用。先用手工承诺表验证，不新增资金或排期系统。

冻结记录另含：冻结对象（原文、剧情事实、已拍镜头或素材）、是否允许候选修改、批准者、解除条件。不能把“前 20 集已粗搭”自动解释为“前 20 集文字不可改”，也不能把“整体检查”解释为可覆盖所有已采用素材。

产物由 M1 生成，M5 保存版本；M2 读取可用边界，M3 读取已确认能力/资产约束的相关部分，M4 核对违规依据，M6 消费真正影响制作的条件。

### 4. 规则与失败处理

- 状态：`captured → needs_clarification / usable_with_unknowns → confirmed_for_scope`。确认针对指定条件集合与用途，不存在“一次确认永远全项目通过”。新条件产生新版本。
- 继承：项目明确约定优先于工作室偏好；同权限来源互相矛盾时保留 disputed，请相关责任人定夺，不能按文件时间自动挑选。
- 没有预算：允许写候选；禁止声明成本达标。关键成本项不明时，M6 不给出制作放行建议。
- 数值规则只由明确条件映射到已有 episode-check 支持项；不能把“最多两个物理场地”偷偷映射成“最多两个地点标签”。不可表达的约束另留人审，不塞入错误的数字代理。
- 时长的 estimated 与 measured 必须分列；字数估算不得迁移为实测。
- 低成本方案必须保留场面承担的因果和情绪功能。删群演、删变化特效时列出牺牲与替代，不接受“全部改口述说明”作为默认策略。
- 中途预算降低，M5 标记依赖旧条件的估算和 M6 放行依据待重核；正文事实不因此自动改变。

自动：字段、数值合法性、来源存在性、快照匹配、范围冲突。模型：条件提取、替代场面与损失分析。真人：资源是否真的可用、硬约束确认、预算与风险承诺。

### 5. 输出给人的最小视图

一页 Brief：本轮必须守住什么；哪些有证据；哪些未知会影响下一步；当前可以做什么；不能声称什么。详细字段是 AI 和检查器维护的记录，不能要求导演手写结构化数据。

## Where

目标仓库复用：`skills/drama-studio/references/initialization.md`、`planning.md`、`writing.md`、`episode-check.md` 与 `scripts/checks/episode_check.py`。

拟新增：`references/production-brief.md`、`templates/production-brief.md`；公共元数据检查交 M5，约束解析继续复用已有逻辑。项目产物放 `planning/production/`，不放安装目录。

## Tests

- 空预算、未知演员与显式 0 值必须区分；非法单位和 NaN 不可用。
- “优先两处地点”不自动变为硬限制；已确认“本批不增加物理场地”不能靠少写场标题绕过。
- 同一资产“已有”与“无使用权/不可访问”的冲突要保留，不算可复用。
- 用户缩短预算周期或替换资产版本，依赖的 M6 记录失效，未依赖的叙事审查可保留历史有效性。
- 一场含多人变身、破坏和复原，不能因为场数为 1 就被认定便宜。

测试映射：[F01–F04、F34–F35](acceptance-scenarios.md)。

## Acceptance Criteria

- M1-AC1：每项 hard 条件具有可定位授权来源、单位或明确非数值语义、有效范围；否则不能按硬约束执法。
- M1-AC2：未知条件可保留且不自动补值；用户能看出其阻止的是哪个结论/动作。
- M1-AC3：冻结对象、事实与候选修改权限分别可查；没有镜头证据不得声称复用。
- M1-AC4：条件更新后，受影响的检查和放行证据进入重核清单，原记录仍可读。
- M1-AC5：替代制作方案同时列明故事功能保留与损失，由相关岗位确认，不能只优化统计。

## Human Acceptance Demo

给导演看一段“1 场、多人形变、道具爆裂”的合成样例，只提供“沿用资产”这一句。预期系统先列现有证据与未知，不给预算通过；导演补一个实际道具状态限制后，编剧收到明确的可选修法。

拒收信号：系统自行承诺片长、把少场景当低成本、要求用户填完几十项才允许试写、或把已有粗搭自动冻结为不可修改正文。

## Anti-Requirements

不新增统一字数/镜头门槛；不自动访问团队私盘；不采购、不收费试镜；不以“条件齐全”证明好看；不把缺预算变成阻止所有写作的理由。

## Context

迁移旧项目时只从来源恢复已知项，未记录的批准不补签。试点成功标准是导演能据此指出具体制作风险而非再次口头说“拍不了”；填表时间和风险提前发现率须实测，不写假收益。

本模块先手工验证字段和用户负担，再接 M5 版本契约；无需等完整生产资产系统。本轮已获方案修订与继续推进授权，实际预算与责任人仍未知；不影响离线准备，但不支持真实放行或全量自动化投入。
