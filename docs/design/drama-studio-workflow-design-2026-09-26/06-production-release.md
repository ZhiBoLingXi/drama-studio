# Release small production batches using measured evidence

M6 · 小批次制作放行 · 设计状态：红队修订 v2；仅手工指南/模板已落源码，未实现放行引擎。

## English Summary

Separate creative approval from production release. Require version-matched editorial evidence, shot-level feasibility and measured trials before a named batch is recommended for production.

## Problem

完整正文、场景变少、模型说好看，都不保证视频团队能按现有资产和预算做出来。本次项目约 20 集粗搭后停下，说明验证时间点太晚的风险已经现实发生；但没有实际成本账，不能断言哪种制作方案盈利。

模块要把最昂贵的未知提前暴露，并让失败只影响相关批次。它不是要求开写前完成全剧分镜，也不是让 AI 替导演签字。

拥有：批次制作准备证据、试制结果、放行/退回决定和当前适用性。边界：M4 判正文问题，M1 提供资源约束，M5 追版本；付款、派单、采购、收费生成和远端发布都不属于自动放行。

## Requirements

### 1. 导演拿到什么

1. 选定候选批次，看到每集准确版本、前后衔接、保留镜头与待改项。
2. 围读/节奏试排，记录对白、动作和停顿如何组成片长，指出不可表达或拖沓处。
3. 拆为可执行镜头或制作单元，映射角色、资产、特殊状态和未知工艺。
4. 优先验证最可能失败的难镜，而不是只做最容易成功的展示镜头。
5. 编剧修正发现的问题，核对修正是否仍被原试镜覆盖。
6. 导演确认表达可行，制片或被授权责任人确认资源和风险，得到仅适用于本批版本的放行或退回结论。
7. 下一批继续；本批实际返工和工时回流 M1，不把计划值当实际值。

### 2. 方案取舍

| 方案 | 优点 | 风险 | 选择 |
| --- | --- | --- | --- |
| 全剧写完且自查后一次性投入制作 | 交接次数少 | 最晚发现资产/节奏缺口 | 不作为默认试点 |
| 只测试一个漂亮镜头 | 便宜易展示 | 不能代表整批承接、动作和成本 | 可探索，不足以放行 |
| 小批次完整拆解 + 风险镜头试制 | 较早暴露不可执行点 | 多一次协调，需真实团队投入 | 推荐 |

试点建议每批 3–5 集，可按用户实际排期调整；这不是默认片长/场数标准，也不改变写作≤10集批次与两次创作审批。批次太短可能看不到长线问题，所以另查阶段/季间接口，不能用小批次代替整季结构评审。

P0：交接包、实际围读记录、拆镜覆盖、风险试制、版本比对、责任人决定、回退原因。P1：跨项目工时分布和难镜经验库；缺长期数据不推导经营预测。

### 3. 放行对象与证据包

对象是 `release_scope`：明确项目、集/场、正文修订、制作条件修订、拆解版本、资产版本与目标产出。可按镜头局部放行，但不得因此写“整批已放行”。

| 证据 | 必要内容 | 不能替代它的东西 |
| --- | --- | --- |
| 授权与稿件 | 当前任务范围、采用/选用版本、冻结边界 | 文件存在、名字叫终稿 |
| 文本核验 | 本批编辑审查、连续性和衔接、未解决阻断项 | 作者状态账、数值检查绿灯 |
| 围读/试排 | 执行人、日期、版本、读演范围、测量方法、时长与问题 | 字数换算、AI 配音粗估 |
| 拆解 | 集场→镜头/制作单元，角色、物件外观状态、地点/资产、动作、声音、转场 | 场标题数、仅角色总名单 |
| 高风险验证 | 风险类别、样本镜头、输入条件、结果、可推广范围、失败/补救 | 只展示成功截图 |
| 资源与成本 | 可用资产证据、估算区间/来源、已发生工时/费用分列、未知项 | 未核价格、模型说省钱 |
| 人工决定 | 谁批准哪一版本哪些范围、前提/有效条件、未放行范围、复核需求 | AI 自动“导演通过” |

围读实测的是读演条件下时长，不等同最终成片时长；镜头试排/粗剪对高动作占比集更重要。只有相应实际证据才能提升相应时长结论，不能一个 measured 标记覆盖所有阶段。

同一物件的完好/破损/烧毁、同一角色不同年龄或形态，必须作为制作状态识别。复用应有素材标识与状态兼容证据；“已粗搭 20 集”不能直接计算复用比例。

### 4. 放行决策与阻断条件

提交状态：`preparing → evidence_ready → pending_human_decision → released / held`。后续输入变化使当前适用性变为 stale；原 released 决定保留历史，不能删除真实发生过的批准。

适用性统一采用公共枚举 current / stale / unknown；needs_revalidation 只存入 `next_action`，不是第四种适用性状态。历史 released 与当前 stale 可以同时存在。

推荐放行必须满足本批作用域：

- 授权与稿件版本明确，未改越冻结/权限边界。
- 必要编辑审查完整且适用；每个 finding 已分流。核心 confirmed 缺陷阻断；核心 suspected、unresolved、影响未定或尚未分流项至少 needs_evidence，均不得 eligible。普通编辑建议/审美意见不自动阻断，但保留创作负责人的取舍。独立审查缺失不得冒充已满足该项。
- 本批拆解覆盖齐全；未知高风险镜头有处理结果，不能因为总成本估计看似低而忽略关键失败点。
- 片长与资源要求有适合其用途的证据；若目标片长尚未指定，不声称片长达标，应由责任人明确本批制作条件后再决定。
- 导演与制片责任按实际团队授权记录；同一个人可兼任，但不能凭角色名称推定其财务权限。

资源检查必须合并同一时间窗内其他已放行未执行和已授权试制的占用；不能只看本批静态估算。每次放行与实际开工前复核会变化的档期、素材权利/访问、报价有效期。过期或撤回使相应证据 stale；未核实则 unknown，不靠正文 hash 未变继续放行。取消/缩减一批后明确释放对应预约，不删除历史支出或历史决定。

普通偏好未满足不自动阻断；关键未知是否阻断由它对本批可执行性的影响决定。风险接受必须记录具体人、风险、范围、原因和补救；不改变事实标签，不把“未测但愿意试”变成“已验证”。

如责任人选择探索性试制，记录为 `experiment_authorized` 的独立动作许可，不能伪装 released 达标；只允许明确范围内试制，费用另需授权。系统不替人支付或生成付费视频。

### 5. 失败、改稿与回退

难镜失败：保留失败条件和样本，提出保留情绪/因果功能的替代方案；原方案与新方案都保留，不能只删失败记录。替代涉及剧情变化，回 M2/M3/M4；仅制作表达变化仍需导演判断。

试前由责任人约定本项目接受标准、尝试/费用/工时上限、停止条件与目标推广范围；未知就先补约定，不启动收费试验。试后登记全部尝试的标识与条件、可用数量、总工时/费用、失败原因及条件变化；参数/资产改变后的尝试不能混成同一可靠性样本。一例成功只能证明该例成功。推广必须重估后续需求与可承受成本，由真人接受依据，不设通用成功率合格线，也不以最终成功掩盖超预算。

正文变化后，M5 判断哪些试镜/实读证据仍相关。例：只改角色姓名不必重做运动试验，但对白时长证据可能因换词需要复核；把持铃改成碎铃必须核对道具与后续镜头。不得在旧视频上贴新版本号冒充验证。

部分通过：已获许可且不受影响的制作单元可继续；共享依赖不明的范围暂缓。停止投入不等于删除已做素材；整理保留/可复用/须返工/未知清单。

跨季结尾放行须包含 M2 handoff 和 M4 对指定后季依赖的核对；不能把下一季尚未写完说成已全部通过。

自动：证据存在、来源和版本、覆盖、条件一致、决定范围。模型：风险识别和修法比较。导演：表达与执行效果；制片/授权负责人：资源、风险和本批投入决定。

### 6. 如何证明流程有价值

试点同时记录：开始制作前发现的可执行性缺陷、投入后才发现的逃逸缺陷、每批返工原因/工时、记录维护工时、原始估算与实际差异。缺分母不报告比例；没有对照不归因于本工作流。

首批全部顺利不证明长期有效。需跨至少不同风险类型观察，也要保存误拦截（本来可做却被不必要阻止）的案例。营收、投流和利润需要独立经营数据，不属于文本或试镜验收。

## Tests

- 正文完整、逻辑通过、场数少，但无拆解/试制：不得给生产 ready。
- 有围读时长但动作镜头大量未验证：不得给成片片长已核结论。
- 难镜失败但普通镜头通过：只能许可明确、无失败依赖的范围，不能放行整批。
- 导演批准 v1 后改为 v2：旧批准不删除，不自动适用 v2。
- 相同资产名但外观状态不匹配：不可认定镜头可复用。
- 缺独立审查或付费授权：可以明确有限探索许可，不能暗中视为正式放行或自动收费。

## Acceptance Criteria

- M6-AC1：放行精确到版本和范围，具备实际责任人及所需证据；未知不填通过。
- M6-AC2：围读、试排、粗剪和成片的测量阶段分别记录，估算与实测不混淆。
- M6-AC3：难镜试制有风险覆盖与失败记录，不用成功展示片替代。
- M6-AC4：输入变动可撤销当前适用性但保留历史；部分继续/暂停的依赖清楚。
- M6-AC5：批准创作、批准探索试制、正式制作放行、付费执行与经营结果五者分离。
- M6-AC6：交接包不要求导演读完所有机器字段；能一页看到可做、暂缓、原因及下一动作。

## Human Acceptance Demo

取 3 集原创或经许可的试点稿，其中一集含未经验证的形态变化。导演完成围读和拆解，难镜试验失败，制片尚未确认替代预算。系统应允许保存所有成果并提出局部修法，不给整批绿灯，不触发收费重试。

当修复及相应验证完成后，由实际负责人选择指定版本放行。该真人步骤未来必须真实执行；本设计没有预填任何导演意见。

## Anti-Requirements

不把试制授权当无限费用授权；不以低字数/少场地证明利润；不自动派单、上传、发布；不删除失败素材；不让每批制作审批阻止已获授权的其他正文写作；不把一个镜头通过推广到整季。

## Context

M6 的独立产品目标是让制作团队在投入扩大前做出有依据的小范围决定。实际试点需要导演、制片和可访问素材；缺这些不阻断设计，但阻断真实复工验收。

建议首试第 11–15 集候选及其第 10 集入口，只作试点范围建议，不等于用户已批准恢复付费生产或覆盖粗搭素材。
