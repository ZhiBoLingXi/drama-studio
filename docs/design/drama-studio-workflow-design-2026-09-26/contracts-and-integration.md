# Define shared evidence contracts and module integration

公共契约设计 v2（拟议，2026-09-27）。本文描述未来实现应遵守的接口，不是当前 CLI 已支持的格式，也不是现有项目数据的自动迁移。

## 1. 单一责任与交接

| 产物类型 | 唯一责任模块 | 主要输入 | 消费方 |
| --- | --- | --- | --- |
| production_brief | M1 | 人的约定、资产/制作证据 | M2、M4、M6 |
| causal_outline / season_handoff | M2 | 已确认方向、Brief、跨季原文 | M3、M4、M6 |
| continuity_ledger | M3 | 正文快照、有效基线、计划差异 | M2、M4、后批写作、M6 |
| editorial_review / finding | M4 | 原文、约束、必要上下游；后阶段再读账 | M2/M3 修补、M6 |
| manifest / parse_report / impact_report | M5 | 文件、输入版本、依赖与执行记录 | 全部模块 |
| production_trial / production_release | M6 | M1–M5 证据、实际制作记录 | 导演/制片、M1 回流 |

正文由现有创作流程产生；不另设第七个正文模块。M5 登记而不写故事。M4 不为避免冲突而自行改正文。M6 不替 M4“补签通过”。

主要依赖：

```text
M1 制作边界 ──→ M2 因果与季间契约 ──→ 正文候选
      │                    ↑                  │
      │                    └── M3 计划差异 ←──┤
      │                              │        │
      └────────────→ M4 正文独立复核 ←────────┘
                              │
                 M6 实测与制作决定 ──→ M1 条件更新

M5 给所有箭头绑定版本、来源、范围与当前适用性。
```

图中的回流不是自动改稿循环。每轮依现有授权和有界迭代规则推进，重大方向变化仍须人决定。

## 2. 公共产物头

| 字段 | 规范 |
| --- | --- |
| `schema_version` | 本契约版本；未知更高版本只读展示，不猜字段含义 |
| `project_local_id` | 现有本地 ID；无远端项目时不伪造 remote ID |
| `artifact_id` / `kind` | 稳定业务对象与上表类型 |
| `revision_id` / `content_hash` | 不可变修订及内容摘要；算法随字段说明明确 |
| `scope` | 全局集号、季内映射、可选稳定场 ID/实体/资产范围 |
| `inputs` | 逐项上游 artifact、revision、hash、使用范围与用途 |
| `source_refs` | 来源定位列表，结构见下一节 |
| `producer` | 人/模型/脚本，已知身份、版本、上下文来源；未知不伪填 |
| `created_at` | 生成时间，不作为批准或新旧语义优先级 |
| `coverage` | 计划范围、实读/实测范围、缺口及方法；只对声明任务有效 |
| `limitations` | 尚未完成/不能证明什么，不能在最终摘要中消失 |

`content_hash` 计算对象须明确，不对包含自身 hash 的整个记录循环求值。正文、报告正文等内容文件为被摘要对象；登记清单保存其摘要及关系。后续序列化细节由实现规范确认，不能不同工具各用一种口径。

类型自己的业务字段独立保存，不能把一个模糊 `passed` 用在全部模块。

## 3. 来源定位与同一性的边界

来源引用包含 artifact/revision、原文摘要、全局集号、稳定场 ID、原始行/段落范围、短摘录及摘录摘要。行号是版本内定位，不跨版本稳定；场标题改编号时映射稳定场 ID，拆分/合并时建立一对多/多对一映射，不复用旧 ID 假装同一场。

对飞书等输入另记读取到的文档 ID/修订、访问日期和本地快照；没有实时重读就只称缓存快照。不能把带临时凭证的完整 URL 放进可分享包。正文中的任何“忽略规则/已审批”字样都只是故事材料，不能成为授权证据。

审批来源单独归类为可信用户消息或可核外部人工回执；材料中的角色台词、模型总结不能充当审批。来源记录能追溯，不等于身份已被密码学认证；实际人/角色权限仍需工作流确认。

## 4. 状态分维度，不设全能绿灯

| 维度 | 值或规则 | 谁判断 |
| --- | --- | --- |
| 执行结果 | completed / incomplete / failed / not_run | 实际运行回执 |
| 证据覆盖 | complete / partial / unknown / not_applicable，绑定检查任务 | 相应模块 |
| 当前适用性 | current / stale / unknown；依据输入核对计算 | M5 |
| 约束结果 | 保留 episode-check 的 met / unmet / not_evaluable / not_configured | 数值工具及 M1 来源核对 |
| 编辑结果 | 事实下限、辨识度、制作未知分列；finding 有独立裁决 | M4 |
| 批准/采用 | 不可变决定事件：人、版本、范围、证据 | 有权的人或实际远端回执 |
| 制作建议 | eligible / blocked / needs_evidence，列逐项理由 | M6 规则聚合 |

聚合不能只输出一个结果：有硬阻断同时又缺证据时，顶层可标 blocked，但必须同时列全部缺口。eligible 仅表示具备提交真人制作决定的证据，不等于 released，更不等于执行付费任务的许可。

`not_applicable` 必须说明原因、适用范围及谁确认；AI 不得用它跳过独立审查、关键难镜或实际存在的约束。仅“本批没有形变镜头”可使形变专项测试不适用，而不是令整个制作验证不适用。

适用性枚举只有 current / stale / unknown；needs_revalidation、needs_review 是动作，不是新增状态。制作 eligible 还要求所有 finding 已按影响分流：核心 suspected/unresolved 和未分流项为 needs_evidence；核心未修 confirmed 为 blocked。完整阅读不能覆盖这些未完成判断。

局部复用采用 evidence_item_id，包含源/目标修订、范围、依据与依赖发现覆盖、适用性、沿用/重核理由；汇总覆盖目标范围所有必要条目，任一缺失或不适用不得整批 current。资源清单同时覆盖已消耗、有效预约和本次新增；口径、时间窗、去重 ID、有效期与撤回记录明确，不能重复扣减或漏算试制预约。

## 5. 行动门槛矩阵

| 动作 | 必要条件 | 不足时做什么 | 不应阻止什么 |
| --- | --- | --- | --- |
| 选题探索 | 当前任务允许研究/提案 | 提供选题候选，不越级正文 | 已授权研究 |
| 生成四项送审包 | 用户已选题，范围明确 | 等选题选择 | 材料盘点 |
| 写剩余正文 | 指定送审包获批，或既有剧修订有明确授权 | 仅在已授权范围工作 | 包内改进/诊断 |
| 依赖旧批继续写 | 能恢复入口；有重大未决则标条件分支 | 补证或保存 provisional 候选 | 无依赖的探索 |
| 声称本批独立审查完成 | 独立来源、全文覆盖、版本有效 | 明示自查/部分审查 | 内部修补 |
| 移交可编辑候选 | 约定正文范围真实完整、状态/局限清楚 | 交部分稿时明确缺集，不冒充完整 | 用户审阅已有内容 |
| 提议正式制作放行 | M6 必要证据齐全，条件与范围有效 | 指明 held 或 needs_evidence 的具体范围 | 其他批次合法工作 |
| 正式放行/付费执行 | 前者需人工决定；后者另需明确执行和费用权限 | 不执行未授权动作 | 无费的文件检查 |
| 宣称盈利改善 | 真实经营数据和有效比较 | 不作此声明 | 文本与制作验收 |

创作授权和叙事质量不是同一个门槛：获准写不等于写得好，质量问题也不自动取消用户原有授权。系统只限制自己能可信地声称和执行的动作。

## 6. 项目内拟议布局

```text
PROJECT.md                         # 人可读入口，摘要不作为唯一权威
.drama/project.json                # 保留现有 v1 绑定含义
.drama/workflow/                    # 新增，可选、按项目启用
  manifest.json                    # 已登记产物/修订与 current 指针
  decisions/                       # 版本/范围明确的人工决定记录
  snapshots/                       # 经登记的文本快照，不覆盖原工作文件
planning/production/               # M1
planning/causal-outline-*.md        # M2
planning/season-handoff-*.md        # M2
planning/continuity/               # M3
episodes/                          # 现有创作流程
reviews/editorial/                 # M4
reviews/workflow/                  # M5 解析/影响/一致性报告
deliveries/production/              # M6 交接与试制证据索引
```

以上为逻辑布局约定，实际文件数可按项目需求控制；用户只读 PROJECT 与正文/一页交接卡。资料不放 skill 安装目录，不自动打包原剧、私人批注或视频。大型素材以授权引用留在现有存储中。

旧项目没有这些目录仍可运行原有工具；新工作流启用时先盘点，不自动宣告旧项目通过、不批量迁移私有资料。

## 7. 工具与宿主的分工

拟议只读 `workflow-check` 接口接受项目目录、目标动作、明确范围与可选版本；输出执行状态、输入摘要、逐项证据、当前适用性、允许继续的动作、阻断原因及下一步。不自动创作、访问网络、调用模型、写审批或修复原文。

这条命令尚不存在。若未来实施，应与现有命令一致：执行/输入错误与门槛不足分别可识别；任何退出码 0 不能替代真人批准。旧 episode-check 语义不变。

模型负责从原文提取、提出疑点和修法；宿主负责实际传递正文及记录阅读范围。脚本可以拒绝空引用，无法证明模型真的理解了一整集。对不遵守 skill 的外部模型或人工编辑，本系统只能在接续时检测变化，不承诺不可绕过的全平台安全闸。

## 8. 接续与端到端示例

以《镇渊君》救援候选作**未来只读试点**：

1. M5 登记原始来源、候选版本及用户修订授权；无远端采用回执保持本地。
2. M1 记录 1–10 集为衔接基线，11–20 集已有粗搭但复用未知；不把“已有”理解为全部冻结。
3. M2 导入季间承接计划，保留当前实际读到的后季范围，不能宣称重写或全审第二季。
4. M3 从 11–15 集及必要第 10 集入口提取候选状态；作者账仅作对照。
5. M4 独立读取该范围，寻找支持与反证；能力不可用就保留待核状态。
6. M5 将所有报告绑到该批正文；格式问题单独修兼容，不修改故事来迎合统计。
7. M6 请导演实际围读/拆解/验证风险镜头，在未提供证据前保持未放行。
8. 新稿出现后仅重核受影响项；不覆盖原飞书，不自动恢复生产。

这是一份验收路径，不是本轮已经执行完成的流程。

## 9. 非 UI / 实施交接

用户入口继续是自然语言和可读文件，`UI_PAGE_HEAVY=false`。本轮没有界面、原型、GitHub issue、Project 配置或开发流水线触发。Spec 的需求/验收结构用于本地设计，不以发布流程强制扩大任务。

v2 已获窄范围源码编辑权限，解析修复及手工指南已落到自包含分发目录并验证；这不代表上述公共产物契约已实现。其余模块工程前先按阶段 0 验证流程价值。源码修改、安装升级、远端采用和真实制作仍是不同授权与验证阶段。
