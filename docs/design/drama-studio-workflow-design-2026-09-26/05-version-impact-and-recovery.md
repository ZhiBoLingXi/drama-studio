# Bind evidence to revisions and recover without overwriting user work

M5 · 版本、修改影响与恢复 · 设计状态：红队修订 v2；仅窄解析修复已实现，完整模块待试点。

## English Summary

Bind every derived artifact and approval to exact input revisions. Detect external edits, invalidate only demonstrably affected evidence, and preserve all user work when recovering a serial local workflow.

## Problem

原文改了，旧的“已检查”报告还留在目录里，下一轮容易误当当前证明；文件名叫 final 也不能说明它已获采用。另一方面，任何修改都重写全剧，会浪费预算、覆盖用户修改并制造新的连续性问题。

当前 recovery 已规定保存版本和核对摘要，但没有通用产物清单、依赖、状态汇总和解析覆盖契约。M5 是六模块的公共底座，不负责判断剧本好坏。

拥有：产物身份、输入版本、来源定位、依赖影响、当前状态投影、恢复记录，以及公共解析结果身份。边界：不制造审查结论、不批准正文、不掌握远端 canon、不承诺多宿主同时写入安全。

## Requirements

### 1. 用户旅程

1. 接续任务时看到当前正文版本、授权范围和哪些检查仍有效。
2. 用户或编剧修改一集，系统先保存新旧区别，不回滚用户文件。
3. 用户看到影响说明：直接改变什么、可能牵动哪些集、哪些证据需要重做。
4. 在原授权内重提取和复核，未受影响部分不机械重写。
5. 中断后重开，仍能从文件与回执恢复同样状态；外部提交响应不明时先核对，不重复提交。

### 2. 备选方案

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 按文件名/修改时间判断最新 | 简单 | 不知道输入关系，不能确认采用 | 不足 |
| 仅依赖 Git 提交 | 历史可靠、差异清楚 | 用户稿可能不进 Git；审批/解析/语义依赖未表达 | Git 可辅助，不作为业务状态 |
| 项目内版本化产物与依赖清单 | 与现有目录兼容、可移交 | 需维护引用和失效逻辑 | 推荐 |
| 新建云端版本/协作服务 | 并发和权限空间大 | 越过当前产品所有权和成本范围 | 不纳入 |

P0：不可覆盖的已登记快照、显式 current 指针、输入摘要、依赖、变更影响、来源映射、状态汇总、串行恢复。P1：更精细的语义影响建议与远端回执适配。不是做一个通用内容管理平台。

### 3. 版本与权威

每个产物：`artifact_id` 标识逻辑对象，`revision_id` 标识一次内容，`content_hash` 标识实际字节，`schema_version` 标识契约，`inputs` 标识上游，`scope` 标识集/场，`producer` 标识产生方式，`created_at` 仅作记录。

同一文字复制到新目录不获得新的审批；相同摘要不意味着获授权；相同事件意思但文字改动也不能直接复用旧原文引用。语义相近与字节相同必须分开判断。

当前选择分为 `working_revision`、`reviewed_revision`、`adopted_revision`、`released_scope` 等投影，不压成单一 project.status。投影从历史记录计算，禁止为了显示绿色手工修改布尔值。

批准、采用、放行是带人、原话/回执、版本和范围的决定事件。新版本出现不会抹去旧批准，只表示旧批准不当然适用于新版本。继续写作的授权范围按既有 approval-flow 判断，不能把所有措辞修正都当整包批准失效。

### 4. 依赖与失效规则

依赖边包含：上游 artifact/revision、集/场/实体范围、用途（解析/状态/故事承诺/制作条件）、显式或推断、确定性、检查类型。语义依赖不是现有工具能够自动完整发现的事实，需要 M2/M3/M4 补证。

| 变化 | 必须重核 | 不应自动改变 |
| --- | --- | --- |
| 空行、标题格式、标点 | 解析/引用映射；必要的原文引句 | 核心故事方向和授权范围 |
| 道具转移/伤势/知识获知 | 当前账、依赖它的后文与相关审查 | 无依赖的支线事实 |
| 季末生死/关系/能力变化 | 季间 handoff、后季依赖、相关放行 | 全剧所有句子 |
| 场景/演员/资产变更 | 制作拆解、试镜适用性、成本估算 | 无叙事变化时的因果结论 |
| 制作预算/片长条件变更 | 相应规格与 M6 决策依据 | 已发生故事事实 |
| 解析器/规则版本变更 | 对应派生统计与适用判断 | 人工批准的历史存在性 |

输出三类范围：确定受影响、可能受影响、已证明不受影响。对未知依赖先保守标 needs_review，再通过定向核查缩小范围；不能声称依赖图完整，从而漏掉远端后果。失效针对结论的“当前适用性”，不是删掉旧文件。

已证明不受影响必须附独立依赖发现记录：查询对象与别名、实际检查范围、原文引用、未覆盖区域、判断人/模型来源。空依赖表不能证明无影响。先用隐藏缺陷位置及依赖边的盲测验证发现能力；不足时保持阶段级或更宽待核，不先启用精确自动复用。

即便只有一个场改变，整份旧报告也不能直接成为新版整批证明；允许创建新汇总，逐项引用仍有效的原场面证据与已复核差异，并明确新版本映射。

可复用单位是 `evidence_item_id`，不是整份报告。每项记录结论、原修订与目标修订、精确范围、依据引用、依赖发现覆盖、当前适用性、沿用/重核理由及核查者。旧报告整体 stale 可以保留历史，其中条目只有进入新的目标版本映射后才参与新汇总。汇总对目标范围逐项检查：缺项、stale 或 unknown 均不能得到 complete/current。任何一项可用不意味着整批可用。

### 5. 公共解析契约：解决真实格式脱节

M5 拥有原文定位和解析产物契约；episode-check 仍拥有文本统计，M3/M4/M6 消费解析覆盖信息。不是新增第七个业务模块。

P0 支持现有 `场11-1 地点 夜 外`，以及已出现的 `### 11-1 地点 夜 外`；集标题沿用现有识别能力。必须在合法集正文上下文识别场标题，普通编号、对白、引用块不可误认。

时间标签接受明确原文并保留原值，例如“黎明、后半夜”；不能只为少量枚举而丢掉整个场。无法确定地点/内外时保留已知字段并标缺失。场号所属集与当前集不一致时给错误/待修，不能悄悄归并。

输出分开记录：原文版本、解析器版本、集覆盖、场标题识别、正文分类覆盖、未识别区间、地点标签映射覆盖、规范化映射。coverage 使用 complete / partial / unknown / not_applicable；“完整”只指声明的语法覆盖，不等于语义已理解或物理资产已核验。

零个识别结果是“recognized_count=0”；当存在未识别标题时，总场数和相关统计完整性为 unknown/partial，不能发布“全剧 0 场”结论。地点标签数永远不等于已核物理场地数。

选择直接兼容解析，避免要求用户重写正文格式；如必须规范化，只生成可对照的新副本，保留逐段源映射，不原地覆盖、不借规范化重写情节。`---` 等明确排版符单独识别，不能当动作，也不能把所有未知行都忽略。

兼容现有 episode-check schema v2 的含义：无配置时仍为 `passed: null`；退出码 0 仍非质量通过。工作流聚合使用独立 schema v1 包装引用旧结果与覆盖数据；若后续需破坏性变更，另立版本并更新文档和回归测试，不能静默改旧调用方。

### 6. 中断、外部编辑与恢复

恢复顺序：读授权和工作区绑定 → 核对当前文件摘要 → 检查未完成产物/未知提交 → 比较已登记快照 → 计算证据适用性 → 给出下一步。

文件被外部修改时登记为待纳入新修订，保留原历史，不“修复”成旧快照。只缺报告可重算；缺原文时不能从摘要伪造原文。草稿写到一半不得成为 current 完整稿；一组产物只有在完整登记后才能作为可交接集合，中断状态可识别。

本地仍只支持单写者串行交接。实现须检查预期工作版本与实际版本不符时拒绝发布新 current；这不是跨主机锁或全文件事务保证。检测到另一写入者时停止冲突发布，保存候选并请求协调，不删除他人锁或文件。

远端：未部署/未授权时保持本地。提交结果未知先读回实际回执；不能因本地有文件就填 remote_synced。专业采用能力缺失时，不通过通用写块绕过。

自动：摘要、身份、引用、覆盖、显式依赖传播、当前状态投影。模型：语义变化分类与潜在依赖。真人：冲突稿选择、重新采用、扩大授权。自动化只能约束本工具和遵循 skill 的工作流，不能阻止用户在外部编辑器改稿。

## Tests

- 用户外部改稿后重开，旧审查保留但不成为当前通过；用户字节不被覆盖。
- 前一集交接删除，影响下游物件使用；仅标点变化不重写整季。
- 语义影响无法确认时标可能受影响，而非自动跳过。
- 解析两种场标题得到相同场边界；未知地点不得用 0 通过上限约束。
- 中断在产物生成与登记之间，重开不读半成品为正式 current。
- 无远端回执保持未知；旧 schema、旧安装目录和用户私有配置不被静默升级。

## Acceptance Criteria

- M5-AC1：所有当前结论能追到输入版本，hash 不匹配即不可直接沿用。
- M5-AC2：变化有范围化影响清单；未知不能悄悄当未受影响，旧记录不删除。
- M5-AC3：外部修改和中断可在新进程恢复，用户稿与历史批准均保留。
- M5-AC4：两类场标题有明确兼容测试，解析不完整不会伪装成低场数/低成本。
- M5-AC5：既有 CLI 含义和配置边界保持兼容；新状态维度不伪装为已实现旧字段。
- M5-AC6：无独立服务、无多宿主并发安全承诺、无自动远端采用。

## Human Acceptance Demo

在测试副本中完成 11–15 集检查，人工删去 12 集的一次交接，再重启宿主。系统必须展示旧批准仍存在、新稿发生变化、哪几处待重核；不能恢复删除句、覆盖用户稿或把整季全部宣布无效。

再给一份 Markdown 场标题稿，显示实际识别与未识别范围；导演能理解“标签统计”和“物理场地核对”不是一件事。

## Anti-Requirements

不使用 final 文件名作为权威；不建立新云同步/锁服务；不自动修改已安装 skill；不自动 commit/push；不因摘要相同证明质量；不把操作完成视为业务验收；不从聊天记忆猜造批准。

## Context

本模块技术先行但不吞并其他模块的业务判断。依赖地图逐步建立，不能承诺一次提取找到所有影响。

旧项目导入只读优先：先生成盘点与待补证据清单，经用户接受再登记副本；不批量迁移/覆盖所有个人项目。正式实现仍需项目源码路径写权限与单独实施安排，本设计本身不触发这些动作。
