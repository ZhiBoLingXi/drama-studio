# Connect character choices, episode consequences and season handoffs

M2 · 因果集纲与跨季承接 · 设计状态：红队修订 v2；待真实试点，未实现完整模块。

## English Summary

Extend existing outlines with causal obligations and versioned season handoffs. Preserve genre-specific emotional promises without treating plans as events that have already happened.

## Problem

“每集有事、有反转、有钩子”仍可能连不成故事：下一集需要的人、道具、能力没有被前一集送到位；为强化季末悬念提前兑现第二季设定，反而使下一季开场失效。

用户明确本剧由一个长剧本拆成两季，季末钩子必须依据第二季。M2 不负责把结尾写得更响，而是建立可兑现的季间契约；没有读到的第二季不能被描述为已核对。

拥有：故事计划、因果依赖、情绪承诺和跨季交接。边界：计划不等于正文事实；M3 负责从正文提取，M4 负责独立判断成立与否。

## Requirements

### 1. 用户旅程

1. 编剧查看已确认方向、原有完整集纲和必须保留的设定，得到当前故事承诺。
2. AI 找到卡点前后的关键选择和后果，展示“缺连接”而非先加台词。
3. 对最关键的断裂提出 2–3 个不同因果方案，说明人物选择、收益和代价。
4. 选定候选后，为下一批列入口条件与待兑现事件；不自动改变已批准的核心方向。
5. 季末对读下一季开场及其依赖，得到“本季收什么、留什么、下季必须接什么”的交接卡。
6. 正文完成后回填兑现位置，未兑现仍是计划，不能用集纲替正文过审。

### 2. 方案比较

| 方案 | 收益 | 风险 | 选择 |
| --- | --- | --- | --- |
| 每集强制几次反转、几个爽点 | 易统计 | 机械重复，动机被指标绑架 | 拒绝通用配额 |
| 把所有动作建成细粒度剧情图 | 可详查 | 填写成本和形式复杂度盖过写作 | 非 MVP |
| 保留现有集纲，增加关键因果链与承诺账 | 兼容创作，能查重要依赖 | 需要语义审查，不可能全自动 | 推荐 |

P0：完整集纲覆盖、阶段目标、关键选择/后果、入口出口条件、未兑现承诺、跨季对读、偏离审批提醒。P1：候选结构对比与历史回收模式。不要将类型模板当剧情答案。

### 3. 三个粒度，避免表格膨胀

**整季契约**：主角欲望与阻力；题材情绪承诺；核心关系轨迹；本季必须兑现的结果；可留给下季的问题；不可擅改的设定与结局。甜宠可以是信任增长，悬疑可以是认知改变，不强制所有作品牺牲或伤亡。

**阶段因果链**：阶段目标 → 阻力/信息 → 人物可选路径 → 实际选择 → 结果 → 下一阶段的必要性。重大逆转须说明前因；阶段可以相对不可逆，单集不必每集发生永久创伤。

**逐集增量**：沿用已有集纲字段，补充新增事件或关系/信息变化、入口需求、出口计划、承诺/兑现位置。静场也可有效，只要人物或观众的理解确有变化；不是把“新增动作数量”作为合格线。

每个关键因果项至少含：`event_id`、集/场计划定位、行为者与目标、可见前提、选择、后果、依赖 ID、证据状态（planned / supported_by_body / contradicted / unresolved）、当前正文引用。仅模型觉得合理，不得标 supported_by_body。

承诺项含：`promise_id`、向观众提供的信息、观众合理期待、计划兑现范围、实际兑现引用、延后理由、是否影响季末可交付性。不用“悬念很强”替代承诺描述。

### 4. 跨季 handoff 的专门设计

| 契约项 | 内容 |
| --- | --- |
| 来源 | 两季所用正文/集纲版本及实际阅读范围；第二季完整稿缺失则注明 |
| 本季收束 | 本季主冲突具体解决到哪里，哪些情绪债已经偿付 |
| 季末状态 | 人物位置/伤势/关系/认知、关键物件、未完成行动；引用 M3 候选账或已采用基线 |
| 新危险/新问题 | 必须由既有选择或已铺设信息生出，不是凭空换一个更大敌人 |
| 下一季入口 | 第 61 集或第二季首集的行动前提；使用全局集号和季内集号映射 |
| 后续依赖 | 开场之外哪些既定揭示依赖此结尾，逐项定位；抽查不能冒充全季审查 |
| 不能提前消耗 | 下季仍要完成的救援、身份、能力、关系变化等 |
| 失败分支 | 下季版本不同、来源不足、首集无法承接时，提供候选尾钩而不覆盖定稿 |

判定一个季末钩子至少回答：人物此刻要立刻做什么？观众为何关心？第一个后续场面能否接住？本季是否已经交付足够满足？不以问号、黑屏或喊名的数量判断。

### 5. 正文反向约束计划

流程：`outline_candidate → package_approved → tracked_during_writing`。正文可以在原授权内局部优化；偏离重大人物关系、题材承诺、冻结结局或审批范围时，保存结构候选，不能默认为批准延伸。

M3 报告计划未发生时，M2 有三种选择：补写所需动作、修改下游计划、放弃该因果方案。不能把“集纲写过”认定为正文已完成。

当缺少第二季全文：读取已提供开场与关键依赖，报告可核范围；可写临时钩子候选，但阻止“已完成跨季校验”的声明。不是阻止所有第一季内部写作。

自动：集号唯一与覆盖、引用存在、缺失节点、显式循环提示。模型：动机、替代选择、情绪兑现、套路与独特性。真人：核心方向取舍、重大偏离许可。图上的环可能是悬疑回溯，不能自动判剧情错误。

## Tests

- 集纲说交出玉铃，但正文未写交接：下集不得把计划当持有证据。
- 第一季末已经救回某人，第二季首集却仍在初次营救：必须给出真实版本冲突；不能无依据补成梦境。
- 下一季首集承接成立，但后面关键身份揭示被季末提前消耗：交接卡必须指到该依赖，不只对读两集。
- 合理留白、隐瞒、回忆、情感递进不因缺大反转而失败。
- 框架局部调整不自动要求重新选题；核心关系改变不被“继续”自动批准。

测试映射：[F05–F08](acceptance-scenarios.md)。

## Acceptance Criteria

- M2-AC1：每个关键转折具备前提、选择、后果、来源或明确未决标记；单有事件清单不合格。
- M2-AC2：每集能说明其新增价值；不存在默认反转/创伤数量门槛。
- M2-AC3：跨季交接覆盖季末、下季入口与已知后续依赖，明确实读范围和不能提前消耗的内容。
- M2-AC4：计划与正文事实区分；未兑现项不得自动升级为已发生。
- M2-AC5：重大偏离提示审批边界；局部授权内修改不重复发起整包审批。

## Human Acceptance Demo

给编剧两版合成结尾：A 视觉震撼但解决了下一季需要的冲突，B 本季兑现后由主角选择引出下一危机。要求系统逐条对照下一季开场及关键揭示，而非按刺激程度投票。编剧应能看见选择 B 的依据以及 B 仍损失了什么。

拒收信号：只评价“够不够炸”、擅造未读第二季内容、让所有题材变成不停反转的同一种剧。

## Anti-Requirements

不新造未授权第二季；不靠符号识别钩子；不要求每场不可逆；不把低场数优先于人物动机；不拿结构完整证明爆款；不因流程更新重启既有修订项目的选题审批。

## Context

本次救援项目可提供真实跨季引用格式，但不是公开测试素材；对外分发用原创匿名片段。M2 的产品验证应让编剧说明“修改前无法接、修改后为什么接得上”，而不是只交一张填满的表。

独立设计时可以先用小型人工样例验证因果项的颗粒度；与 M3 集成后再验证计划/正文差异。现有双审批保持不变。
