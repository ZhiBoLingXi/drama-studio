# Derive continuity states from versioned screenplay evidence

M3 · 正文状态账 · 设计状态：红队修订 v2；待真实试点，未实现完整模块。

## English Summary

Track consequential state transitions from actual screenplay passages, keeping plans, candidate facts and adopted canon separate. A ledger is a navigational aid for review, not independent proof of narrative consistency.

## Problem

长剧分批写作时，作者容易记住“剧情大意”，却忘记谁受伤、谁知道秘密、物件在谁手里、能力用完有没有代价。把摘要塞给下一轮模型只能减少遗忘，不能证明摘要本身正确。

本次救援已有人物/物件状态账，但它来自主编提取，仍需对照正文。新模块应防止三个混淆：计划冒充事实、作者解释冒充原文、候选变化污染已采用版本。

拥有：正文可定位的状态变化与批次入口/出口。边界：M2 拥有未来计划，M4 负责反证审查，M5 保存版本，正式远端采用仍由 mali-story 管理。

## Requirements

### 1. 从编剧的下一步反推最小账本

1. 接续前读当前有效正文、采用基线、上批出口和未决项，不只读聊天摘要。
2. AI 提取会限制后续行动的实体、状态与变化，并标出原文依据。
3. 对歧义只记待核实，不补造一次未写的交接、治疗或信息传递。
4. 下一批写作使用入口状态；允许提出改变，但必须让改变在正文中发生或有合理依据。
5. 写完后再从新正文提取出口，比较“原计划/实际发生”，列差异交 M2 与 M4。

不记录每次眨眼和随口一句话；只记录会约束后文或影响制作连续性的事项。重要性由具体依赖决定，不以固定行数限制。

### 2. 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 滚动摘要 | 轻 | 容易丢证据、误把推测写成事实 | 可作阅读入口，不作唯一账本 |
| 全文逐句建知识图谱 | 查询丰富 | 实体歧义、维护量大、引入新基础设施 | 暂不选 |
| 关键实体状态 + 带引用的变化记录 | 可追溯且可局部更新 | 提取仍需复核 | 推荐 |

P0：人物、关键物件、知识、能力/限制、时间线、关系/承诺的必要变化；入口出口；计划差异；候选/采用隔离。P1：跨季状态搜索、可复用的题材专属字段。基础模型不锁死仙侠。

### 3. 三层事实空间

| 空间 | 允许来源 | 使用规则 |
| --- | --- | --- |
| `planned` | 集纲、设定、开发假设 | 写作目标，不能作为已发生证据 |
| `candidate` | 指定候选正文 | 可在同一候选分支内接续；不能覆盖正式事实 |
| `adopted` | 有明确采用记录的正文版本 | 已采用基线；本地账仅记录其来源，不冒充远端写入成功 |

“批准送审包允许继续写”不自动等于“其中所有未来计划都已发生”，也不等于远端正式采用。采用范围可以只是部分集数；混合基线必须列出每段版本，不能拼接后给一个假统一版本。

### 4. 实体、状态和变化契约

实体 `entity_id` 稳定；显示名、别名、身份揭示与实体本身分开。不得只因两个称呼相似就合并人物，也不得因为“玉铃/铃铛”叫法不同就断言是两件道具。

每条关键状态包括：实体、属性、值、所在故事时间/支线、叙事出现位置、事实空间、来源引用、确定性、依赖的变化。值允许 unknown、多个有条件候选，不把未知写成“无”。

| 类型 | 重点属性 | 常见漏项 |
| --- | --- | --- |
| 人物 | 位置、在场/受控状态、伤势、行动能力 | 受伤后无解释恢复；被押解却自由行动 |
| 物件 | 所有权、实际保管人、所在位置、完整性、替身/副本 | 所有者不等于持有者；破损仍用完好外观 |
| 知识 | 命题、谁知道/相信/误信、获知途径 | 观众知道不等于人物知道；谎言不等于事实 |
| 能力 | 已知规则、前置条件、可用状态、消耗/后遗症 | 方便时突然能用；能力代价写完即消失 |
| 关系/承诺 | 对谁、何种承诺、成立/违背/解除、双方认知 | 口头和解不等于另一方已经信任 |
| 时间 | 故事日/相对顺序、持续时间区间、叙事顺序 | 回忆和现实串线；移动时间未必能精确量化 |

变化记录 `transition_id` 至少有：`entity_id`、属性、before、after、原因/动作、前后引用、转移性质、确定性、故事时间、受影响依赖。

转移性质区分：明示、可靠蕴含、可能发生但未建立、故意隐瞒待揭示。只有前两类能在有依据的范围内支持后续；蕴含必须写推理，不能冒充原文直述。

### 5. 入口/出口与读取范围

每批账含：基线版本集合、本批完整阅读范围、边界依赖范围、入口快照、变化列表、出口快照、未解冲突、应交给后批的限制。

默认读取本批全文、必要的前批承接与被引用旧场面；不以“相邻两集都看过”替代涉及长线物件的回溯。若正文截断或缺页，缺失区间明确进入 coverage，不得宣称完整提取。

“必要旧场面”不能仅由旧账或既有依赖边选出。关键状态变更后，应另作依赖发现：从原文检索实体/别名及相关事件，记录检查过的前后范围、命中与未覆盖范围。检索只是召回辅助，不能用没命中证明无依赖。发现能力未通过无提示盲测前，默认重读受影响阶段及边界；阶段或影响范围也不确定时，将剩余相关正文列为待核，而非给出精确无影响结论。

批间检查至少比较：前批出口与后批入口；后批声称新变化的发生位置；未完成承诺是否被错误清零。场号重排由 M5 映射，引用不能默默指到另一场。

### 6. 处理矛盾，而不是自动改剧情

流程：`extracted → needs_reconciliation / reviewable`；M4 核对后的结果单独引用，不把 extracted 改名为 independent_verified。新正文变化产生新账版本，旧账保留。

发现“物件同时在两人手里”先检查时间、别名、副本、交接、回忆和叙事视角；找不到解释时提疑点，不能生成不存在的幕后转交来消除红灯。

正文与账冲突时以正文为提取来源，修账不等于修文；若正文自身相互冲突，则由 M4 给证据，编剧决定补桥、改后果或保留有意悬念。只修账不能关闭正文缺陷。

缺少上一批正文时，可以在已获授权的独立支线探索；依赖缺失状态的接续须标 provisional，不能升为已验证交付。不要整项目一刀切暂停，也不要偷偷猜入口。

自动：引用可定位、实体 ID 重复、快照与范围一致、显式结构矛盾候选。模型：抽取、别名建议、隐含转移、知识视角。真人/编辑：歧义取舍、正式采用；独立评审由 M4 组织。

## Where

复用 `skills/drama-studio/references/writing.md`、`recovery.md` 的批次接续要求。拟新增 `references/continuity-ledger.md`、`templates/continuity-ledger.md`；机械校验接现有 `scripts/checks/`，但不在 Python 规则中冒充语义理解。

项目产物 `planning/continuity/`；正文保持原有 `episodes/`。候选与采用引用的空间必须可区别。

## Tests

- 同名不同人、同物别名、多副本、所有权与保管权不同都不直接报硬错。
- 回忆里的完整道具与现实里的破损道具可共存；未标回忆而时间含糊则待核实。
- 秘密在旁白里揭示，不自动让所有角色知情；被谎言骗到是 belief 不是世界事实。
- 前集受伤，下集治疗有原文可反证；无治疗也不能仅凭“受伤”断言所有动作绝对不可能。
- 新写候选不修改已采用基线；只改账不能关闭正文中仍存在的断裂。
- 上轮摘要遗漏转交动作，复读全文应恢复动作而非批评剧情。

测试映射：[F09–F13、F33](acceptance-scenarios.md)。

## Acceptance Criteria

- M3-AC1：关键状态和每次转移均可回到指定版本正文，推断与直述分开。
- M3-AC2：planned/candidate/adopted 不可隐式互转，采用必须引用实际授权/回执。
- M3-AC3：入口、出口、批次覆盖与未决项齐全；缺文不标完整。
- M3-AC4：支持不同叙事时间与知识视角；合理别名、回忆、谎言不会被机械判硬错。
- M3-AC5：正文修改触发受影响账的重提取；不依靠聊天记忆恢复。

## Human Acceptance Demo

提供三段匿名正文：第 1 段甲保管铃，第 2 段交给乙，第 3 段乙使用。给 AI 一份故意漏掉第 2 段的作者账。要求从正文恢复合法转移；再移除真实交接句，要求标缺口而非补造交接。

导演应能直接定位物件不同外观状态，编剧应能看出“设定/计划”和“本稿已发生”的区别。

## Anti-Requirements

不把账当第二份剧本逐句重写；不自动补桥；不规定所有能力都有统一代价；不把角色自述都当真；不将提取完成称为独立复审；不直接更新远端 canon。

## Context

M3 独立设计的最小价值是“下一批不再靠记忆猜入口”。失败风险是账很完整但错得一致，所以必须与 M4 的独立读取相隔离。账本列出来源能降低定位成本，但不能单独证明文本质量。

先用原创短片段校准颗粒度，再对现有救援稿做只读试点。保留旧账作为历史；迁移时缺失出处一律标未核实，不伪造新证据。
