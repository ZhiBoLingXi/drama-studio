## 1. 背景与证据

### 1.1 现行流程走了一遍，编剧仍改了六成

该项目第 1–5 集走完了技能 0.3.6 的整套台词流程：C2 写声音卡（K5）→ C5 场面稿 → 台词遍 → C6 台词读 → 一次定向修订。2026-10-12 主创把前五集交给编剧手改。逐句对照（`runs/input/writer-edit-pairs.md`，difflib 行对齐后人工复核）：

| 项 | 数 |
| --- | --- |
| AI 稿台词行 | 104 |
| 编剧稿台词行 | 116 |
| 文字改动 | 63 行（60.6%） |
| 只改括注 | 6 行 |
| 一字未动 | 35 行 |
| 新增 | 12 行（8 行新写，4 行拆句） |
| 删除 | 0 行 |
| 改动行平均句长 | 28.3 → 33.0 字（+16.4%）；改长 49、改短 9 |
| 净增语气词 / 连接词 | +18 / +23 |
| 新加括注 | 17 处，其中情绪形容词占一半以上 |

六成改动率说明现行流程产出的台词离这位编剧要的还远。更要紧的是六条归因，每条都对应本提案的一个设计点。

### 1.2 六条归因

1. **声音卡是假设，不是样本。** 16 张声音卡 r1 的 `evidence.nature` 全是 `creative_hypothesis`，`judgedBy` 写“AI 起草，随人物小传 v2”。编剧稿是项目里第一份人工标注；在它出现之前，流程里没有任何一句真人写的本剧台词。→ §3 分级、§5 提取。
2. **技能通用标准与编剧写法相反。** 对照卡 `pair-overall@r1` 的 `limits.conflicts` 记了三条：`dialogue.md` §5 要求括注只写演员能做的事、不写只有形容词的括注，编剧加的括注一半以上是情绪形容词；地域通用卡 r2 的“不用北方口”“不写四字格”“同一场只叫一次人”与编剧稿不符，r3 才放宽；此外编剧句子更长、不忌讳成语和公务词。技能的规则在这位编剧面前是错的。→ §8 覆盖。
3. **模型学表面特征并加大密度。** 第一轮台词读（10 集，`rev-qx-b01-dialogue.json`）：203 句有声台词里 72 句（约 35%）以“称呼＋逗号”开头，一个称呼被四个人物共用 12 次。第二轮（第 6–10 集按编剧样本重写后，`rev-qx-b01-dialogue2.json`）：前五集 116 句里某个句末语气词只出现 2 次、都属于同一个人物，后五集 115 句里出现 12 次、散到 7 个人嘴里；四个人物的平均句长从 16.0→32.8、15.0→31.3、17.0→38.0、31.6→43.7；一个在前五集说了 14 句的人物后五集只剩 3 句。每一项都是“学到了特征、没学到密度”。→ §7 数数。
4. **台词读与作者同一模型家族，只有被要求“去数”时才数得出来。** 两次台词读的 `claimsIndependence` 都是 false。第一轮没有数句长；第二轮因为任务单要求比较前后五集，才数出语气词和句长的变化。盲测两轮分别 17/20 和 25/25，但两位读者都在 `unknowns` 里写明抽样前已通读全文，是“半个盲测”。→ §7 把数数交给脚本。
5. **每批只修订一次，修订后不再读。** 第 6–10 集修订（e2）后，作者用临时脚本自己数了一遍：语气词 12→4、全部归回那一个人物，句长回落；但 `PROJECT.md` 记“修订后未再做台词读”。改对了多少，现在只有作者自己的数字。→ §7.4 再数、§9 留出法。
6. **`season-check` 只查记录在不在。** 现行三条规则 `voice-card`、`dialogue-pass`、`dialogue-read`（`scripts/checks/season_check.py` 的 `_dialogue`）核对的是：说话人有没有声音卡、台词遍有没有动场头、台词读有没有发生。它们判断不了密度，`dialogue.md` §7 也如实写了“判断不了台词自不自然”。→ §10 新规则。

### 1.3 已经确认的三处改进

主创已同意：**A.** 样本在前、流程在后：新项目先让编剧改一两集，再批量写。**B.** 台词遍存稿前先数：语气词、句首称呼、各人句长等，与范本并排，超了不许存。**C.** 项目的对照卡可以覆盖技能的通用规则。

主创新提：“台词样本要建立知识库，Agent 根据规则去提取样本。”这是本提案的主体。

### 1.4 与两项既有决定的关系

- **D4-5“暂不建工作室共享知识”（2026-10-08）**。那次决定针对 K1–K9 的方法卡，理由是没有增益证据、跨项目失效条件难核。它写了重开条件之一：“主创或导演在两部以上的剧里反复给出同一类修改意见，而且这类意见能写成带失效条件的卡”。台词口语化已经在两部剧出现（镇渊君后 50 集的四版，见工艺闭环设计 §8；本项目三轮），意见类型相同。本提案认为重开条件**部分满足**，但只建议窄范围重开（§11 阶段 4），不建议现在就放开所有知识卡的 studio 范围。
- **D2 门槛“不扩大 K1–K9 生产”（2026-10-06）**。样本库不是方法卡生产：样本是证据（架构 §8.1 的外部材料路线），不是规律。它不与门槛结论冲突，但也不能借门槛之外的名义绕过验证，所以 §9 的留出法是本提案自己的门槛。

## 2. 目标与非目标

**目标**

1. 项目里每一句进包的台词正例都有来源、日期和证据级别；AI 起草的句子不再以“例句”身份进包。
2. 台词遍的产出在存稿前被数一遍，密度与范本并排，数得出的学过头当场拦住。
3. 一个能重复、不靠作者自评的度量：把编剧改过的一集藏起来，流程重写，量与编剧版的距离。
4. 提取、入库、审核、抽检的每一步都标明是脚本能查（S）还是模型约定（M），和技能“如实标注未核实”的原则一致。

**非目标**

- 不训练、不微调模型；不做向量检索；本地工具不联网、不调模型（沿用 `AGENTS.md`）。
- 不自动判断台词好不好。脚本只数，主创看稿决定。
- 不把对标剧的句子变成可照抄的金句库（§6.3）。
- 不在本提案里实现 mali-story 侧的知识存储；工作室级样本先放本地目录（沿用 10-10 决定）。
- 不替代本剧人写正文：有编剧稿时它永远优先于任何库内材料。

## 3. 样本来源与分级

### 3.1 四个级别

样本的价值首先取决于**谁写的、怎么来的**。分级写在每条样本上，和 10-12 文档的权利等级（自有／仅参照／公开许可）是两条独立的轴：权利决定能不能用、能用到什么程度；级别决定它能证明什么。

| 级别 | 来源 | 证明什么 | 能做什么 |
| --- | --- | --- | --- |
| **A 对照** | 编剧“原句 → 改句”，原句是 AI 稿、改句是编剧稿，逐字 | 这位编剧**不要什么、要什么**，差在哪 | 进包为正例＋反例；做数数关口的范本；建覆盖卡（§8）的唯一依据 |
| **B 定稿** | 编剧本人写或改定的台词，含编剧**一字未动**的 AI 句（35 行那一类） | 这位编剧**认可什么** | 进包为正例；做范本；“未动句”是“原来就对、别碰这类”的直接证据 |
| **C 转写** | 已上线剧的拉片逐集转写（带说话人、状态、原话；如 drama-harness 的“Speakers and Transcript”格式） | 这一类人物、关系、地域、年代**在成片里怎么说** | 只学说法：供索引维度检索、补项目没有的人物类型的参照值；不进覆盖卡；成稿对它做 `dup-check` |
| **D 起草** | AI 写的台词、AI 编的例句、现有 `creative_hypothesis` 声音卡的例句 | 只是假设 | **不进样本库**；可以留在声音卡里当假设，但不能作范本、不能作数数的参照 |

规则：

- 级别由来源决定，不由质量决定；Agent 不能因为一句 AI 台词写得好就升格。被编剧**保留**的 AI 句升为 B，依据是编剧的保留行为，不是 AI 的判断。
- 一张卡的级别等于它引用的最低级样本。不建议混级；混了就按最低算。
- 每条样本带 `sourceId`、`grade`、`rights`、`versionOrDate`、`sha256`（来源文件）；缺一不入库（S）。

**与编排方立场不同的地方。** 编排方的排序是 A ＞ B ＞ C ＞ D，我同意顺序，补两点：第一，A 和 B 的来源都是同一位编剧的手，证据强度相同，A 多出来的是“从什么改成什么”这层信息；所以 A 不应在**数量**上压过 B，范本统计要 A、B 合并算（否则范本只有 63 句，太少）。第二，“编剧一字未动的句子”在编排方的分级里没有位置，它是 B 级里最该单列的子类：它直接回答“什么不该学”，本案 35 句里现场口令、客气短句、狠话、群聊应答全在其中，第二轮台词读发现的“把口令也加长”就是没用上这批样本。

### 3.2 C 级的边界

C 级是“真人说出来的话”，量大、现成，但它是**别的编剧**写的、**别的演员**说的、**别的剧**里的。三个限制：

1. 只按索引维度（§4.2）用，不按人物名用；不会出现“让本剧人物像对标剧某个人物”的检索。
2. 不能为本项目建覆盖卡、不能作硬项阈值的参照；只在项目没有 B 级样本的人物类型上，作软项参照，且记录里标明 `referenceGrade: C`。
3. 成稿对 C 级语料跑 `dup-check`，13 字档任何命中都必须改（§6.3）。

转写里的“State”（情绪状态）字段是 ASR 或拉片方标的，不是编剧标的；入库时保留原文但标 `labelSource: transcript`，不与 Agent 标的态度混用。

## 4. 样本对象与字段

### 4.1 为什么要一个新对象，而不是只加几张 K5 卡

现有 `knowledge-card`（`schemas/knowledge-card.schema.json`）的 `content.examples` 是字符串数组，一张卡五到十句。样本库要的是每一句独立可数、可按维度过滤、可核对出处的记录，几百上千条。塞进卡里会让卡过大、让“例句逐字取自原文”没法脚本核对。10-12 文档也把“语料片段”定为新对象。本提案定名 **样本（dialogue-sample）**，卡仍是进包单位，卡的 `examples` 引用样本。

放弃的替代方案：把样本写成 K5 卡的 `evidence.sources[].location#行号`。可以追溯，但维度过滤、统计都做不了，还得解析原文。

### 4.2 样本（dialogue-sample）字段

| 字段组 | 字段 | 由谁填 | 说明 |
| --- | --- | --- | --- |
| 身份 | `sampleId`、`sourceId`、`grade`、`rights` | 脚本 | `grade` ∈ A/B/C；D 不入库 |
| 出处 | `location`（文件＋集场＋行）、`versionOrDate`、`sha256`（来源文件） | 脚本 | A 级另有 `pairedWith`：原句所在文件与行 |
| 文本 | `text`（逐字）、`direction`（括注原文）、`mode` ∈ 对白/OS/电话/群聊文字/录音 | 脚本 | 括注与台词分开存，便于分别数 |
| 项目内索引 | `speakerName`、`addresseeName`、`episode`、`scene` | 脚本（说话人）、Agent（对象） | 只在项目范围有效；提升到工作室级时去掉 |
| 跨项目索引 | `speakerRole`（年龄段＋身份，如“九岁孩子”“中年店主”“民警”）、`relation`（对孩子/对配偶/对公家人/对对手/对陌生人/对兄弟…）、`intent`（命令/哄/骂/辩解/推脱/问/报信/认账/表态/打岔…）、`attitude`（硬/软/怕/得意/不耐烦/客气…）、`situation`（险情/当众/私下/隔门…）、`region`、`era` | Agent；`region`/`era` 取项目设置，不知道写 `unknown` | 取值开放，目录页列实际用到的值，由人合并同义（沿用 10-12 §3.3） |
| 可数特征 | `chars`（去括注）、`endParticle`、`startsWithAddress`、`startsWithInterjection`、`subjectDropped`（启发式）、`directionType` ∈ 情绪词/对象/动作/无 | 脚本 | `subjectDropped` 和 `directionType` 标 `heuristic: true` |
| 标注状态 | `labelSource` ∈ agent/human/transcript、`reviewedBy`、`reviewedAt` | 脚本记录 | 抽检后填 |
| A 级专有 | `pair.before`、`pair.diffNote` | 脚本（before）、Agent（diffNote） | diffNote 是解释，`evidence.nature` 相当于 interpretation |

存放：`<项目>/knowledge/samples/<sourceId>/samples.jsonl`，一行一条；来源登记 `<项目>/knowledge/samples/<sourceId>/source.json`。与现有 `knowledge/sources/<sourceId>/` 的约定并列：`sources/` 放原件，`samples/` 放切出来的记录。

**与编排方立场不同的地方。** 编排方主张“按谁对谁、想要什么、带什么态度、关系处境、地域年代索引，而不是按人物名”。跨项目复用时对，但项目内的数数关口（§7）必须按人物比：第二轮的问题正是“某个人物的语气词跑到别人嘴里”，按角色类是查不出来的。所以样本同时带两组索引，人物名是项目内键，提升时剥掉。

### 4.3 在现有 knowledge-card 上怎么表达

声音卡（K5）和对照卡（K9）不变形，只加引用：

- `content.examples` 仍是给模型看的字符串，但每一句必须逐字等于某条被引用样本的 `text`（新增 S 规则，§10）。
- 新增可选字段 `content.sampleRefs: [sampleId…]`。有这个字段的卡，`samples validate` 核对例句逐字；没有的卡按 D 级处理，不作范本。
- `evidence.sources[]` 新增可选 `grade`。
- 对照卡的 `examples` 现在是“原句 → 改句”一行文字，保留；`sampleRefs` 指向 A 级样本，脚本从样本的 `pair.before` 与 `text` 重建这一行核对。

### 4.4 需要改 schema 的地方（单列，全部是计划）

| 对象 | 改动 | 阶段 |
| --- | --- | --- |
| 新 `dialogue-sample.schema.json` | `$id: drama-studio/dialogue-sample/v0`，字段见 §4.2 | 1 |
| 新 `dialogue-stats.schema.json` | 数数关口的记录，见 §7.3 | 2 |
| `knowledge-card.schema.json` | `content.sampleRefs`（可选）、`evidence.sources[].grade`（可选，enum A/B/C/D） | 1 |
| `knowledge-card.schema.json` 与 `contract_check._rules_knowledge_card` | `scope.level: studio` 仅对 `knowledgeType: K5` 且全部 `sampleRefs` 为 C 级或为“去句子的特征摘要”放开；`scope` 增加可选 `originProjectId`。A/B 级句子的卡仍拒绝 studio | 4，待主创决定 |
| `context-snapshot`、`selection` | 不改。样本只经卡进包，知识分区仍只收 `knowledge_card` | — |

## 5. 提取规则：Agent 做什么

“Agent 根据规则去提取样本”拆成七步。原则：**脚本能做的不让模型做**——切分、对齐、数数、核对出处都是脚本；模型只做标注和分组。每步写输入、输出、失败怎么办、层级。

| 步 | 做什么 | 输入 → 输出 | 失败时 | 层级 |
| --- | --- | --- | --- | --- |
| 1 登记来源 | 问主创一次：这份文件是谁写的（定 grade）、能用到什么程度（定 rights）；脚本记 sha256、日期 | 文件 → `source.json` | 答不出 grade 或 rights → 不入库，记在目录页“待定来源” | M（问）＋S（记录齐全才能进下一步） |
| 2 切分 | 剧本格式按 `season_check.py` 认的台词行（“人物（括注）：话”，名字 ≤10 字）切；转写格式按 Speaker/State/Content 块切 | 文本 → 候选行 | 认不出说话人的行跳过并计数；跳过率 >10% 时停下让人看格式 | S |
| 3 对齐（仅 A 级） | AI 底本与编剧稿按行 difflib 对齐，产出 before/after 对；拆句、并句按一对多记 | 两份文本 → 对 | 相似度低于阈值的对标 `alignment: uncertain`，不计 A 级，等人确认 | S（对齐）＋M（确认） |
| 4 标注 | Agent 填 `addresseeName`、`relation`、`intent`、`attitude`、`situation`、`speakerRole`；`region`/`era` 从项目设置取 | 行＋上下文（本场） → 标注 | 不确定写 `unknown`，不编；`unknown` 的维度不参与检索 | M；schema 校验取值格式 S |
| 5 数特征 | 脚本算 §4.2 的可数特征 | 行 → 特征 | 启发式项标 `heuristic` | S |
| 6 成卡 | Agent 把同一人物（项目内）或同一索引组合（跨项目）的样本归成 K5/K9 卡，`examples` 逐字取样本，`counterExamples` 取 A 级的 before | 样本 → 卡 | 例句与样本不逐字相同 → `samples validate` 报错，卡不算有效 | S |
| 7 审核与抽检 | 入库时编排方或主创看一遍 Agent 的标注；之后每次装包前脚本随机抽 N 条由人核标注 | 卡＋样本 → `reviewedBy` | 抽检错误率超过约定（首版建议 20%）→ 这批卡退回 `pending`，不进包 | M（判断）＋S（抽检记录在不在、`pending` 的卡不进包） |

提取规则本身写成技能的方法文档（计划名 `references/dialogue-samples.md`），Agent 按它执行；规则改了出新修订，样本上记用的是哪版规则（`rulesVersion`）。

**与编排方立场不同的地方。** 编排方写“提取规则由 Agent 执行”。我把切分、对齐、数数都划给脚本，Agent 只剩标注和分组。理由是本案的对齐和统计已经由脚本做过一遍（`writer-edit-pairs.md` 的数字是 difflib 脚本数的，人工复核），模型做这几步只会更慢更不稳；而且脚本做的部分天然是 S 级，正是契约要的。

工具命令（计划）：`drama_tools.py samples {register|harvest|ingest-transcript|validate|stats|promote}`。`harvest` 就是工艺闭环设计 §4.2 第二通道里“暂不做”的那个比对工具——本案已经用临时脚本做了一次，说明需求是真的（见 §12 待决 3）。

## 6. 检索与进包

### 6.1 怎么选

装 `dialogue_author` 包时，知识分区按这个顺序填，满了就停：

1. 本集出场人物的声音卡（K5，`sampleRefs` 全部 A/B 级）——必装，`voice-card` 规则已要求。
2. 本集出场人物的对照卡（K9，A 级）——按人物取，优先最近确认的。
3. 本集出场人物里**没有** A/B 样本的（新人物、群众），按 `speakerRole + relation + region` 检索 C 级样本卡——每人最多一张。
4. 现有 `creative_hypothesis` 声音卡——只在 1–3 都没有时装，卡上已有“未经主创审核”标注。

选哪几张由模型判断，`knowledge search` 按字段过滤（沿用“工具不做相关性排序”）。

### 6.2 预算与防过度套用

- 知识分区不超过包的四分之一（已有规则）。
- **每张卡随卡附密度**：卡的 `mechanismOrFact` 里必须有“本剧范本里这个说法多少句出现一次”的数字（由 `samples stats` 算出，Agent 抄进去）。第二轮学过头的直接原因是卡里写了“这个人物有这个口癖”却没写“116 句里 2 次”。
- **同一句例句不连续两批出现**：`context-pack` 记录每张卡装进过哪些集（10-12 §4.4），第二批起跳过上一批用过的例句（M，脚本只记录）。
- 包里例句前固定一句话：“学说法，不照抄句子；每个说法的密度见卡，不加大。”（M）

### 6.3 只学说法不抄句：与反同质化、dup-check 的关系

架构 §8.3 把反同质化分到知识供给、创作工位、审读三处。样本库是知识供给，它带来的新风险是**抄句**，分三层挡：

| 层 | 对什么 | 怎么挡 | 层级 |
| --- | --- | --- | --- |
| 供给 | C 级样本 | 不按人物名索引；卡上 `transfer.notTransferable` 固定写“原句不可照搬”；不进覆盖卡 | S（字段必填）＋M |
| 创作 | 作者 | 包内说明；例句靠近写作指令但只给说法 | M |
| 审读 | 成稿 | `dup-check --new <本集> --source <C 级语料全文>`：13 字档任何命中列出必改；8 字档只报。对本项目自己的 B 级语料另跑一次只报不拦（同一部剧重复口令是正常的） | S（跑了、命中列出来）；改不改是 M |

`dup-check` 现在只给百分比；需要加 `--list-hits` 输出命中的片段和位置才能当修改单用（计划，§10）。它仍然“不是原创证明”，这句话不改。

## 7. 存稿前的数数关口（B）

### 7.1 数什么、和谁比

参照集 = 本项目 A＋B 级样本（按人物；某人物不足 8 句时退到 `speakerRole` 同类的 B 级，再不足退到 C 级并标 `referenceGrade: C`，再不足就 `no_reference` 只报不判）。

| 指标 | 怎么算 | 硬／软 | 本案对应的问题 |
| --- | --- | --- | --- |
| 专属语气词泄漏 | 参照集里某个句末语气词 ≥80% 属于一个人物且 ≥2 次，则其他人物该词次数 | **硬：0** | “吧”2→12 散到 7 人 |
| 句首称呼比例 | 以“≤4 字＋逗号”开头的台词占比，全批与按人物 | **硬**：≤ max(参照×1.5，参照＋5 个百分点) | 72/203 |
| 叹词开头比例 | 以常见叹词开头的占比，按人物 | 硬：同上 | 一人物三连叹词，参照 0/19 |
| 平均句长 | 去括注含标点，按人物 | 软：\|本批 − 参照\| ≤ max(25%，5 字) | 四人翻倍 |
| 句数份额 | 每人物台词句数 ÷ 总句数，与参照份额比 | 软：参照 ≥10% 的人物本批 <3% 报“失声” | 14 句→3 句 |
| 括注密度与类型 | 每句括注数；情绪词／对象／动作三类比例 | 软 | 参照 17/116；“只写动作”规则被编剧否定 |
| 固定短语跨人物重复 | ≥4 字短语在 ≥3 个人物嘴里出现 | 软 | 报数句式、同一信息三遍 |
| 场头与行数 | 场头逐行同前稿（已有规则）；台词行增删数 | 报 | — |

阈值放在项目的 `planning/dialogue-spec.json`，**不自动发现**（沿用 `episode-check` 的做法）；上表里的倍数是首版默认，来自一个项目的一次经验，第二个项目要重新校。编剧稿自己的句首称呼比例本案还没算过，阶段 0 第一件事就是算出来。

### 7.2 硬与软为什么要分

**与编排方立场不同的地方。** 编排方和主创的说法是“超了不许存”。我只对硬项这么做。理由在第 6–10 集修订记录里：某人物修订后平均句长仍比参照高 8 字，作者写明“剩下的长句是讲欠条的两段戏，再压就要删事实”。句长、份额、括注这类指标会被本集的事件合理推高，一刀拦会逼作者删事实来凑数，这比学过头更糟。所以软项超标允许存，但 `run-handoff` 里必须逐项写原因（M），stats 记录随交接留下，台词读能看到。硬项（泄漏、句首称呼、叹词）没有“剧情需要”的例外：它们是纯写法。

### 7.3 记录与“不许存”怎么成立

本地工具拦不住 `update_page`：存页面是模型经 MCP 做的。“不许存”落成一条可查的记录：

- `samples stats <项目> --episode <n> --text <本集稿> --reference <参照配置>` 输出 `runs/<批>/dialogue-stats-ep-<nnn>.json`：参照集的样本 ID 清单与 sha256、被量文本的 sha256、每项指标的值与状态（`within`/`exceeded`/`no_reference`）、总状态（`within`/`exceeded_soft`/`exceeded_hard`）。
- `season-check` 新规则 `dialogue-stats`（S）：台词遍存下的那个修订，有一份 stats 记录，`measured.sha256` 等于回执里的指纹，总状态不是 `exceeded_hard`。改完再数、再存才有一致的指纹——这就是“超了不许存”在契约里的形态，和 `dialogue-pass` 核对场头是同一种做法。

### 7.4 修订后再数、再读

每批一次定向修订之后：

- **再数**（S，必做）：对修订稿再跑一次 `samples stats`，规则 `dialogue-stats` 对修订后的修订同样生效。成本是一次脚本。
- **再读**（建议 S，待主创定）：只装被修订的台词行及其所在场，新上下文 `dialogue_read`，不装全集。包很小，比整批重读便宜；它回答“改的这几句像不像”，再数回答“密度回来没有”。两者都有才算证明“改对了”。

放弃的替代方案：每批修订后整批重读。成本翻倍，而且修订只动了十几句，重读全集大半是重复劳动。

## 8. 项目覆盖通用规则（C）

### 8.1 机制

技能通用规则（`dialogue.md` §1、§5 等）在编剧明确写法不同时让路。覆盖写成 K9 卡：

- `content.problem` 以“覆盖：”开头，写明被覆盖的规则位置（如“dialogue.md §5 括注写法”）；
- `limits.conflicts` 写规则原文的要点；
- `sampleRefs` 只能引用 **A 级**样本，至少 3 条（一两处例外不算编剧的写法）；
- `usage: creative_reference`，`processing: curated` 需要主创确认过（`judgedBy` 写主创确认日期），否则 `pending` 不进包。

`context-pack` 把覆盖卡排在知识分区最前，包头生成一行“本项目覆盖技能规则：……”（M）；`knowledge search --overrides` 列出项目所有覆盖卡（S）。覆盖只在本项目有效，不进工作室级（它是这位编剧的写法，不是通用知识）。

优先级从高到低：主创当次原话 ＞ 覆盖卡（A 级） ＞ 声音卡／对照卡（A/B 级） ＞ 技能通用规则 ＞ C 级参照 ＞ D 级假设。C 级不能覆盖技能规则：对标剧是别的编剧的写法。

### 8.2 现有三条冲突怎么办

`pair-overall@r1` 的 `limits.conflicts` 三条，按上述机制：括注情绪词一条、北方口／四字格／称呼频率一条，有 A 级样本支撑，可建覆盖卡，待主创确认；小名一条是事实口径不是写法，走 C4 变更提案，不是覆盖。

放弃的替代方案：直接改 `dialogue.md` 把“不写形容词括注”删掉。那是把一位编剧的写法推给所有用户；下一位编剧可能恰恰要动作括注。规则留着，项目覆盖。

## 9. 留出法评测

### 9.1 问题

现在能说的只有“编剧改了 60.6%”和作者自己数的密度回落。要回答“改进后的流程离这位编剧近了多少”，需要一个藏起答案、能重复、不靠作者自评的测法。

### 9.2 做法

- **材料**：编剧改过的 5 集，各有三份：场面稿（c5r1）、AI 台词遍稿（d 版，编剧改稿的底本）、编剧稿（w1）。
- **留一法**：对第 k 集（k=1…5），样本库只允许装入**其他四集**的 A/B 样本；从第 k 集的场面稿起跑台词遍（新流程：样本卡＋数数关口），产出 p_k。编剧稿 w1_k 全程不出现在任何包里。
- **零样本基线**：现有 d 版对 w1 的距离，就是“声音卡全是假设”时的结果，已经有数字（63/104 改动等），不用再跑。
- **对齐**：p_k 与 w1_k 按说话人序列锚定再 difflib 行对齐，沿用 `writer-edit-pairs.md` 的口径（拆句、并句按一对多）。

### 9.3 指标

| 指标 | 算法 | 回答什么 |
| --- | --- | --- |
| 需改句比 | 对齐后与 w1 不同的 p 行 ÷ p 行数；另报归一化编辑距离 >0.3 的行占比 | 编剧还要动多少 |
| 该留的留住了 | 编剧未动的 35 行那一类（d 与 w1 相同的行）里，p 与 w1 仍相同的比例 | 有没有学过头去改对的句子 |
| 特征距离 | §7.1 每项指标在 p 与 w1 上的差，按人物，报向量不合成分 | 密度像不像 |
| 副作用 | p 新设的事实（人、物、数字在场面稿和集纲里都没有）、行数增减、场头变化 | 为了像而编事 |
| 泄漏检查 | 所有装包材料与卡例句对 w1_k 做 13 字 shingle 命中；命中即该次作废 | 答案有没有进包 |

只报数字，不合成一个分；解释写在报告里。

### 9.4 怎样避免对着指标过拟合

1. **留出集只读、每次使用记账**：w1 五集是考题。每跑一次记进 `runs/eval/holdout-ledger.json`；同一集被用作留出超过 3 次就退为“已见回归”（架构里 43–44 集的做法），不再用它报泛化。
2. **阈值不从留出集定**：§7.1 的参照来自样本库（其他四集），留出集只用来量结果；谁拿留出集的数字去调 `dialogue-spec.json`，这一轮结果作废。
3. **多指标并报**：某一轮“需改句比”降了但“该留的留住了”也降了，说明是整体改写而不是学会了；两者要一起看。
4. **副作用单列**：D2 门槛报告里“为满足卡片新设事实”的教训直接搬过来。
5. **距离不是好坏**：这个度量量的是“像这位编剧”，不是“台词好”。编剧版是一种写法，不是唯一正确答案。所以每个阶段末仍要一次主创盲选（10-12 §6 的 M2），留出法只是让盲选之前的迭代有数可看。
6. **N 很小**：5 集、1 位编剧、1 部剧。报告必须这样写，不说“流程有效”，只说“在这位编剧的这 5 集上距离从 x 到 y”。

**与编排方立场相同但要补的。** 编排方提的留出法我全部采纳，补了“该留的留住了”和“泄漏检查”两项：前者是本案第二轮最典型的失败形态（把不该动的口令也加长），后者是评估隔离区（知识设计 §2.1）的硬要求，没有它留出法可以被卡例句无意间破掉。

### 9.5 放在哪

- 评测方法与合成夹具：`evals/dialogue-holdout/README.md`（计划），夹具用自编文本。
- 真实运行与报告：留在项目 `projects/<项目>/runs/eval/`，不入库；仓库只放不含私有句子的结论页（和 `docs/d2/knowledge-gate-report.md` 同一做法）。
