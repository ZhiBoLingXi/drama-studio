# 模拟新用户安装与创作测试

测试当前 main；记录实际 commit、宿主、版本与人工介入。使用新会话和新的工作目录，不复用维护者的稿件／评审。私有仓库要求用户与 AI 的 GitHub 访问环境有读取权限。克隆源码不等于安装技能，安装文件不等于宿主已发现。

## 1. 让 AI 从仓库安装

复制发送：

> 请浏览 https://github.com/ZhiBoLingXi/drama-studio ，读取当前 main 的 README.md、INSTALL.md 和 docs/hosts.md，按我正在使用的宿主安装 Drama Studio。先检查已有安装，保留我的配置和修改。分别验证技能文件、宿主发现、本地工具、mali-story MCP授权与模板读取，记录本次源码commit。不要启动创作、上传视频或收费任务；需要登录时给出授权入口。若当前入口不支持安装，说明具体缺口，不把阅读说明当作安装成功。

ChatGPT 先确认桌面还是网页。桌面独立技能可在 Skills 中检查并用 `@` 选择；本地使用 Codex 安装路径后还须验证当前模式发现。网页插件尚未发布，不能仅靠把 ZIP 作为附件上传宣称已安装。详情见[宿主指南](hosts.md)。

## 2. 从新选题到完整初稿

技能可发现后，在新会话显式选中它并发送：

> 使用 drama-studio，先问我题材、受众和制作条件，再给出三个核心冲突不同的原创选题。等我选定后，完成六集完整初稿、连续性审读和一轮有依据的修订。保留原稿和修订稿，交付正文、当前设定／集纲、问题清单与接续说明。不要复用仓库测试故事。不得提交收费拉片；能读取已有模板时如实检查其覆盖与来源，资料不足不得伪造已完成研究。

先让用户选择，再写完整稿。检查实际结果：不是只有梗概；主线和结局可理解；人物关键选择有前因及代价；核心转折没有凭空新增规则；明确制作限制被遵守。把“可继续编辑”“辨识度”“阅读偏好”分开记录。六集通过不证明长剧稳定性，模型自评不替代用户判断。

## 3. 改稿与新会话接续

在交付正文中手动改一处人物决定或台词，再开新会话提供当前项目文件：

> 使用 drama-studio，只依据当前交付文件恢复项目，先说明当前版本和未解决问题。我已手工修改正文；保留这些修改，检查旧检查结果是否过期，并列出受影响的后续集数。先给修改建议，等我选择后再另存新版，不覆盖原稿。

验证它能找到真实修改、辨别已写事实与未来计划，避免覆盖手改或用旧报告证明新稿。云端无法读取本机文件时主动提供交接文件，不能只说“继续上次”并假定同步。

## 4. 留下可复查的反馈

保存源码commit、输入提示、宿主发现结果、实际工具输出、完整稿、修订对照及你的具体判断。指出最想跳过的一场、最愿意保留的一场、是否必须推翻主线才能接手；不要只报总分。

分别记录安装、MCP业务读取、创作、接续的成功或失败。收费拉片属于另一个场景：没有能保证用户费用上限的机制时不得提交，不影响继续测试已有资料与本地创作。
