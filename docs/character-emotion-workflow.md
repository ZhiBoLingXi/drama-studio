# 人物与情绪修订：流程优化设计

日期：2026-09-28。范围：可分发技能及本地写作/评审工作法；不新增模型运行时、自动评分、云端状态或制作放行服务。

## 根因与改动依据

已有写作和自主迭代规则包含“功能人物”“台词可互换”“工整无感”“不要只补解释台词”，并非缺少这些概念。实际执行仍可能出现以下偏移：

1. 写作入口将评审描述成“查硬伤”，容易先筛事实矛盾。
2. 为防误报，合理地区分事实和审美，但缺少“非硬伤也可能是本轮必须解决的任务”的出口判断。
3. 人物声音要求主要在写后出现，写前常只有形容词与设定，缺角色如何应对压力的场面依据。
4. 连续性容易停在伤势、道具、知识是否接得上，少查心理转折和关系余波。
5. 以“可继续编辑、有部分改善”保留候选，未充分回答用户明确指出的每类问题是否在新版中解决。

上述为流程与文字中可定位的漏洞；不能据此证明所有平淡稿都由同一原因造成，也不推断导演真实停产成本。

## 设计选择

### A. 写作输入：人物的做事办法

复用有效前文，摘出少量人物在常态/受压时的行动与声音依据。写作目标是恢复人物策略，不以增加口癖、人设字段或禁用词表代替。合理成长须有经历支持，不冻结早期人格。

### B. 场面生成：关键尝试、抵抗、选择

在症结处比较不同的行动实现，再写完整对白。对关键怀疑、原谅、识破等转折，核角色实际感知、理解和行动。对反派、权力变化、退路中断，核谁争取、谁阻止、为何失败。不是为每场规定固定节拍。

### C. 跨批次接续：关系也会留下状态

在既有接续记录里带入有后续影响的承诺、信任损伤和行为变化；不新增全表情状态机。人物可以回避、误判、反复，不强制每集正向成长。

### D. 评审裁决：事实、任务目标、偏好分开

事实问题继续查反证；创作目标用正文与用户目标的差距判断达成/未达成/证据不足；开放偏好保留争议。没有硬矛盾不自动关闭任务目标，模型不喜欢也不能无证据升级成缺陷。

### E. 迭代与版本：样段证据先于全稿推广

有广泛同类问题时选覆盖风险的样段比较，记录收益、退步与下游接口。不固定集数，不自行添加人审门槛：用户已授权全稿时可继续；用户要求先看样段时按约定停。旧完整稿始终保留，样段不冒充整剧。

### F. 交付：验收本次要求，而非只验文件

除完整性与事实下限，单独回答本轮人物、对白、情绪目标的状态。修订达到轮次上限可以停，但未达目标仍须明列。程序检查、模型审读、用户采用和制作效果保持分开。

## 文件落点

| 位置 | 改动职责 |
|---|---|
| `skills/drama-studio/SKILL.md` | 新增症状路由，避免具体创作反馈只进入查错 |
| `references/character-emotion.md` | 写前人物依据、场面实现、情绪余波、评审分类与反例 |
| `references/writing.md` | 实际写作前与写后接入新方法 |
| `references/creative-loop.md` | 目标验收进入候选比较和停止条件 |
| `references/development-lab.md` | 保留多样性同时不忽略明确返修目标 |
| `references/delivery-readiness.md` | 交付时不能以可编辑代替意见已解决 |
| `references/recovery.md` | 新会话恢复未达目标和样段范围，旧检查不自动关闭返修 |
| `templates/development-record.md`、`reading-record.md` | 在现有记录中保存目标及正文证据，不增加必填大表 |

表内`references/`和`templates/`均相对分发技能目录。项目私人素材不进入分发包。

## 怎样验证、不能证明什么

- 安装/离线回归：现有50项测试、仓库静态检查、技能结构校验；包括此前工作树已有的解析兼容测试，不全部归为本次新增。
- 合成行为：甲检查“无事实错误但未完成创作目标”；乙保护静场；丙保护有前置代价的直说与成长；丁检查角色获取信息的依据。输入与运行前预期分离，读实际输出，不用关键词自动判质量。见[行为回归](../evals/character-emotion/README.md)。
- 实际使用：按用户指定的7集样段检验人物、心理和对抗目标；只证明这一样段的模型判断及用户随后真实反馈，不能外推全剧或稳定成功率。
- 不宣称保证未来不再发生。后续遇到失败，回查具体入口、任务目标和正文，把失败及成立的反例加入维护；不要因一稿失败再堆一套通用硬指标。

## 本轮实现边界

技能规则已修改并同步当前安装；版本号仍为0.2.0本地修改稿，以文件hash及安装回执区分，不宣称发布新版本。没有提交Git、发布Release、改MCP、启动付费或自动上传。工作树中原有的解析兼容和制作试点改动保留，安装时一并带入，但并非本轮新增实现。

本方案不把抽象六模块全部实现成引擎。它将创作质量要求接入已有的输入、生成、接续、评审、迭代、交付路径，具体效果以真实样段的后续审读为准。
