# 初始化模块设计

状态：2026-09-24，安装协议、随包引导模块与记录模板已落地；尚未实现通用调度注册器。本次设计没有在维护者机器上启用数据采集、创建定时任务、迁移数据库或改变账号配置。

## 产品边界

编剧让 AI 安装后，应能知道：文件装在哪里、数据从哪里来、是否自动更新、什么时间更新、在哪台机器执行、哪些账号已连通、作品保存到哪里，以及怎样修改或停用。安装可以在离线或部分能力缺失时完成，但不能把“文件已安装”统称为“全部可用”。

交付仍是 Skill 加宿主能力。MCP 是连接方式之一：红果优先复用可用的本地采集／查询脚本，mali-story 继续通过其 MCP 提供模板与拉片；不自建模型服务、数据库平台或常驻调度系统。

初始化分三层：

| 层 | 保存内容 | 变更原则 |
| --- | --- | --- |
| 工作室偏好 | 工作目录、常用创作与交付习惯、是否使用某数据源 | 用户可跳过；项目指示优先 |
| 当前运行环境 | 机器、宿主、部署路径、解释器、连接、调度任务 ID 与证据 | 新机器重查；不通过同步文件自动激活 |
| 单部作品 | 集数、对标、新选题、送审版本、采用与费用授权 | 各项目独立；不能从初始化继承审批 |

## 用户交互

入口为“初始化工作室／继续初始化／修改设置／检查状态／暂停或关闭采集”。不新增需要编剧记忆的 CLI；AI 根据随包模块和实际宿主能力执行。

首次流程：自动只读发现 → 展示已有配置与缺口 → 询问工作目录、采集选择、可跳过偏好 → 按选择补问 → 展示具体变更 → 执行已获授权的步骤 → 读回逐项验收 → 保存可接续记录。

首次只问对下一步有影响的事项。选择“不采集”后不追问时区和详情上限；选择本地 Markdown 后不要求飞书登录；只做本地写作时可推迟 mali-story 登录。首次页面不用展示配置字段、数据库表或工具名称。

用户选择每日采集时的预览示例：

> 将复用你已有的榜单目录，每天北京时间 10:00 在这台电脑更新榜单及报告，不运行 AI 解读、不自动下载剧集。本次是否立即更新另按你的选择执行。电脑休眠时的行为和下次实际执行时间将在调度器核验后显示。可以随时说“暂停榜单更新”。

这是交互示例，不是默认计划；频率、时区、范围、执行机器和实际能力必须取自该用户的选择与证据。新用户不会继承维护者的北京时间10点、300积分上限或私人连接。

## 模块组成

| 模块 | 输入与输出 | 本轮实现边界 |
| --- | --- | --- |
| 环境发现 | 已知目录、宿主工具 → 能力清单与未知项 | AI 按现有工具只读核验，不建全盘扫描器 |
| 引导与计划 | 能力、旧设置、用户选择 → 按模块划分的具体变更 | 随包 `references/initialization.md` |
| 配置与证据 | 选择、回执、版本 → 可接续记录 | 随包模板生成用户目录的 `STUDIO.md`，单写者串行维护 |
| 数据入口适配 | 现有部署／导出／连接 → 可查数据和覆盖 | 明确上游真实 CLI；不复制采集器到主项目，不把 MCP 设为必装 |
| 调度适配 | 已授权计划、执行环境 → 实际任务 ID、下次触发、状态 | 使用可核实的已有执行器；通用自动注册器待实现 |
| 验收与修复 | 配置期望、实际任务和数据 → 差异、下一动作 | 分开计划、登记、触发和数据成功，不冒充后台持续监测 |

新会话从当前工作区或用户提供的记录入口恢复；找不到记录先问位置，不全盘搜索或重新初始化。多个工作室分别保存配置；同名非本模块文件不覆盖。

安装脚本继续负责可逆的文件安装、升级与校验。引导不与 `install.py` 强耦合；从 ZIP 安装的用户也能使用初始化模块。升级只替换受管理的技能文件，不改 `STUDIO.md`、作品、数据、凭据和既有任务。

## 状态与授权

每个可选功能分别维护状态，而非一个全局 `initialized=true`：

`未选择 → 跳过`，或 `已选择 → 待环境／授权／参数 → 可应用 → 执行中 → 已验证／部分成功／失败／结果未知`。

调度还要区分 `未开启 → 待配置 → 已登记 → 已观察真实触发`，以及 `暂停／停用待核对／已停用`。首次采集是独立运行记录，不能替代定时触发证据。用户选择开启但应用失败时保留开启意愿，并显示实际未生效，不能修改意愿来掩盖失败。

保存选择来源、作用范围和修订；修改时间与开启采集是两个动作。“改到9点”不能在原本关闭时自动创建任务。用户已给出完整明确授权时不再要求重复确认；需要新选择时先完成不依赖该答案的安装和计划准备。

任务执行结果未知时先查询调度器与数据状态。能够找到唯一的已创建任务才补回执；多候选保持待核对，不重试创建。mali-story 的收费任务仍遵守其服务端预算与幂等契约，初始化不绕过它。

## 数据与定时执行设计

同一数据库只设置一个负责采集的运行环境，其他宿主读取该库的导出或真实服务。唯一标识包含数据源、规范化实际库位置和执行环境；显示名不能作为去重依据。无法枚举另一宿主的任务时，先核实所有者，不以“没看到”作为新建依据。

一期默认询问“不开启／手动／每天更新”；其他周期只有执行器能准确表达时才支持。每天时间以用户选择的 IANA 时区解释，核对夏令时与下次执行的当地／UTC 时间。定时必须指向持久部署和明确解释器，不能依赖交互 shell 激活环境。

建议采集执行不经过 LLM：定时器 → 固定命令与单次运行记录 → 上游快照／报告 → 状态读取。AI 分析在用户主动研究时执行；自动研究、推送和收费拉片是后续独立功能，不附带在“每天采集”里。若只能采用宿主 AI 自动化，需先说明账号额度与应用运行条件，让用户选择。

上游约束来自当前源码检查：数据库固定在组件 `data/`，报告固定在组件 `reports/`；榜单采集更新四类榜单；资料上限只限制详情；榜单和详情分别加锁，未覆盖整个 daily；详情失败可能在榜单成功后返回非零。执行适配不能承诺尚不存在的自定义数据目录、按题材采集或全程互斥。

后续通用执行器的最小实现范围：持久部署绑定、命令参数数组（不拼接用户 shell 文本）、整次运行互斥、任务去重与回执、超时和退出状态、有限恢复、按真实状态读回暂停／变更。必须先选定要支持的 OS／宿主并核对其真实能力；不宣称仅靠当前 Markdown 已实现这些执行保证。

电脑休眠、关机、凭据过期、解释器消失、上游结构变化、磁盘不足或权限变化时记录明确失败，不删除数据、不提权、不购买服务。错过历史采集只记录缺日；补跑只能取得当前可用数据。旧数据可继续用，但附观察日期。原始页面和日志长期留存的磁盘需求应在状态页显示，清理／备份另获授权后才执行。

## 修改、暂停、升级与卸载

配置文件变更前后比较已读内容，检测他人修改；当前只有串行接续，缺少原子配置事务时不能同时让两个宿主应用。先保存计划和旧绑定，再应用并读回。中途失败留下逐项回执，恢复时完成缺项，不回滚或删除与本次无关的用户资源。

修改采集时间应在原受管理任务上完成；不要先新增再留下旧任务。暂停未来触发不等于取消进行中的运行；分别显示实际结果。卸载技能只移除技能，是否关闭其管理的采集任务需根据用户指定范围处理；数据删除始终是另一项明确操作。

云端无持久执行能力时使用导出资料及可下载初始化记录。没有真实远程采集服务就标未配置，不生成虚构 URL，不把沙箱内文件称为跨设备同步。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 首次安装，用户未选择定时 | 询问必要选项；不创建任务、数据库或自动采集 |
| 用户明确不采集 | 保存未开启；继续其他初始化，不追问时间 |
| 仅给“每天10点” | 核对是否开启、时区、范围等缺项，不猜测本地时区 |
| 已有同库任务，要求改时间 | 核对原任务、授权及作用域，修改唯一绑定，不重复建库或任务 |
| 用户只要首次采集 | 运行范围内的一次更新，保持定时关闭 |
| 只要未来采集，拒绝立即运行 | 跳过首次采集；登记与真实触发分开验收 |
| 手动运行成功、定时器创建失败 | 数据可用，定时未生效，保留可恢复计划 |
| 创建调用超时但任务实际存在 | 通过唯一标识找回回执，不重复创建 |
| 榜单成功、部分详情失败 | 部分成功，显示各自日期／缺口，保留旧数据 |
| 休眠、跨时区、新机器、多个宿主 | 核对实际运行条件与同库所有者；不自动复制启用计划 |
| 旧配置或用户修改 | 先读、比较、保留；升级不重置时间、费用或创作选择 |
| 关闭或卸载 | 只操作范围内任务，读回停用状态，保留数据和作品 |
| 没有 MCP 但本地脚本可用 | 正常使用脚本，不诱导为采集安装 MCP |
| 无本地执行的宿主 | 导出／真实远程入口，标记本地调度不可用，不声称注册成功 |

上线调度执行器之前，需用临时任务实际验证至少一次定时触发、跨进程读取回执、重复初始化不重复建任务、暂停后不再触发和保留用户修改。仅通过文件安装测试或模型阅读协议，不能宣布这些场景已验收。
