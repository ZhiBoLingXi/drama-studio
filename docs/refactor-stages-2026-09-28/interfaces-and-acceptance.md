# 跨阶段接口与验收责任

状态：设计契约 v1，待实施验证。继承[总方案](../refactor-plan-2026-09-28.md)的边界；本文件只补充交接和一致性，不把拟议命令描述成当前能力。

## 1. 单一归属

| 契约 | 设计冻结 | 主要生产者 | 消费者 | 必须保留的边界 |
| --- | --- | --- | --- | --- |
| TaskContract / DecisionRecord | R1-02 | 宿主从实际任务／人工决定提取，R2 登记 | R3 选材、R4 目标复核、R6 范围判断 | 项目偏好不等于本剧授权；本地姓名字段不认证身份 |
| ArtifactRevision / EditionManifest | R1-01、R1-03 | R2 登记、R3 候选、R6 导入 | 全阶段 | 精确版本、确切内容摘要、候选／正式来源不混用 |
| ProductionBrief / CausalOutline / SeasonHandoff / ContinuityLedger | R1-03 | R3 从有效计划／正文组织，R7 回传真实制作条件 | R3 写作、R4 审读、R7 试点 | 制作硬要求与未知分开；计划、候选事实与正式事实分开 |
| ContextPacket | R1-03 | R3，联网选材可经 R5 | 写作者、复核者、后批接续 | 主文、作者解释和规则分区；遗漏、冲突不能隐去 |
| ReviewReport / Finding / GoalAssessment | R1-04 | R4 或已验证 R5 审查回执 | R2 新鲜度、R6 交付、R7 试点 | 报告有身份、范围和版本；创作判断不是程序定律 |
| RunRecord / OperationRecord | R1-05 | R2、宿主实际运行 | resume、R5 对账、R6 恢复 | 已完成步骤可恢复；未知结果不默认失败重做 |
| RemoteReceipt / CapabilityEvidence | R1-05 | R5 从实际工具返回登记 | R2 映射、R6 能力展示 | mock、源码、发现、鉴权、业务读写、真实费用分列 |
| ProductionEvidence / DecisionRecord | R1-04、R1-05 | R7 真人及工具记录 | R4 状态聚合、R6 交接、后续修订 | 试制、放行、执行费用许可互不等价 |

每个业务对象必须指向 schemaVersion、项目、范围、输入版本、producer、来源、限制。增加公共字段要同时更新生产与消费测试；不能只改一端。各阶段可用 R1 的冻结 fixtures 开发，但使用替身不代表集成通过。

## 2. 版本、摘要与引用

- `artifactId` 表示逻辑对象，`revisionId` 表示不可变修订；本地 ID 与远端 ID 分命名空间。全局集号是主键，季内编号只是映射，不用章节排序推断集号。
- 原始文本按实际 UTF-8 内容字节计算 SHA-256；不得在计算前静默规范化。来源若经过解码、换行或格式转换，保留原始快照并登记派生关系。
- 元数据指纹使用契约指定的确定性 JSON 序列化，字段顺序、空白和 Unicode 处理在 R1 冻结；首版业务契约不允许不明确的浮点数。正文哈希与元数据指纹分开，不计算自包含 hash 字段的循环摘要。
- 源引用使用版本、集号、可选场 ID、明确单位的半开区间和短摘录。字符位置使用 Unicode code points；字节摘要不拿字符下标直接切片。行号仅是展示辅助。
- 场景拆分／合并时保留映射；初版没有可靠场 ID 时可以只引用版本内范围并标局限，不能生成看似稳定但未经核对的场 ID。
- EditionManifest 精确列出每集正文版本。混用新旧候选是可表达的编辑状态，不等于整季重写、全审或采用。

## 3. 命令边界

R1 冻结以下动作的输入／输出；R2 先实现登记、检查、恢复和最小导出，R3 接 prepare，R6 接 import。既有五个命令不改默认含义。

| 动作 | 必需输入 | 副作用 | 缺口处理 |
| --- | --- | --- | --- |
| inspect | 明确项目目录，可选任务 | 只读 | 无工作流时报告 not_initialized，不自动创建目录 |
| check / workflow-check | 项目、目标动作、任务、适用的 edition | 只读 | 输出 actionDecision 与所有缺口；无条件就不能给合格结论 |
| register | 项目、产物请求、expectedRevision、operationId | 本地追加 | 首次显式登记可初始化可选工作流；冲突拒绝且保留输入 |
| prepare | 项目、任务修订、明确来源列表、expectedRevision、operationId | 本地包登记 | 模型选材、程序核验；不调用模型，不静默截断 |
| impact | 项目、变化起点及范围 | 只读 | 已知依赖传播，未知语义影响单列 |
| resume | 项目、任务／run 标识 | 只读恢复建议 | 不自动重跑模型、付费调用或远端写入 |
| export | 项目、固定 edition、显式新目标目录、operationId | 本地导出；按登记契约记录回执 | 不覆盖已存在且内容不同的导出；不上传 |
| import | 项目、明确旧资料入口 | 默认只读预览；显式 apply 才登记 | 预览后来源变化须重做预览，不自动选择“最新”文件 |

统一响应分为执行、目标动作、范围、输入版本、新鲜度、约束、目标判断、人工决定、限制。`check` 对所请求动作的 `blocked / needs_evidence` 返回 2；`inspect` 成功展示阻断仍可返回 0。输入／执行错误返回 1。所有调用方必须读取结构化结果，不能只看退出码。

`allowed` 只表示某个动作在声明范围内条件满足。例如允许导出待审稿不代表允许宣布本轮目标全部解决。只读命令不能顺手写“最后访问时间”、迁移记录或修复文件。

## 4. 检查与执行的竞态

只读 check 是当时观察，不发永久通行证。register、prepare、import apply 和导出冻结必须在实际动作前重新核对版本／来源；本地提交在锁内核对 expectedRevision，远端动作使用实际服务的快照与 CAS。

本地崩溃一致性承诺只针对经过验证的单机本地文件系统与支持的平台，不承诺硬盘损坏后完整恢复，也不支持网络共享目录的并发写。发现工作文件在读取期间变化时拒绝把混合内容登记成稳定快照，输出需要重新读取。

依赖新鲜度和资源有效性不同：内容未改，报价、授权、人员档期也可能过期。R7 的易变证据带有效期、范围和撤回记录，不能只用文件 hash 判有效。

## 5. 报告、人工决定与可信边界

本地授权记录可以追溯，但没有密码学身份认证。工具拒绝材料内容冒充宿主决定、缺来源和引用不符的记录；不能证明一个可任意改文件的操作者没有造假。正式远端鉴权不得信任本地传入身份。

`coverage=complete` 必须限定任务、目标和实际范围；宿主传完所有文本不等于模型理解全文。独立性单列 `isolated / history_known / self_review / unknown` 等实际来源说明，未知不默认独立。

事实问题可裁定 confirmed、refuted、unresolved；创作目标用 met、unmet、insufficient_evidence；偏好记录选择和代价。修复确认产生新复核条目，旧报告不修改历史。R1 最终 schema 可选统一外层状态，但不得丢掉这三类语义。

## 7. 发布判定与失败归属

- 本地工程候选版：适用工程 AC 完成、R6 升降级可复现、无未解决的数据覆盖／错误采用风险。R5 未验证能力关闭，并显示原因。
- 创作方法版：工程测试不能替 AC-17；对照无收益时可发布技术底座，但方法变更保持候选或回退，不能宣传质量提升。
- 私有样段：R6-06 可以完成交付而用户仍 pending；该结果不授权扩稿。
- 真人试点：R7 可以得出 blocked 或 needs_evidence 的有效结论，不能把“完成试点记录”写成“已放行”。

失败按源头回流：输入错误回 R3-01/02，人物与场面方法回 R3-03/04/05，误审回 R4-02/03，陈旧证据回 R2-05/R4-04，联网未知回 R5-04，资源／片长问题回 R7。修改后通过依赖机制重查相关证据，而不是重跑所有阶段或只改最终报告。
