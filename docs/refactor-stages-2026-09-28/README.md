## 2. 阶段依赖与两条发布路径

    R0 → R1 → R2 → R3 → R4 → R6 本地候选版
               └────→ R5 ─────→ R6 联网能力启用
    R6 七集交付／版本证据 → R7 真人试点 → 反馈回到相关组件

以上是集成次序，具体任务允许在冻结接口后先准备方法、测试材料或适配假数据。不能把可以并行设计解释为可以跳过集成依赖。精确依赖以各阶段任务表为准。

- **本地路径**：R0–R4 完成适用工程验证后，经 R6 的迁移、安装、回退测试交付；R5 不可用不阻塞此路径。
- **联网路径**：在本地路径基础上，只启用 R5 已验证的能力；读、写、审查、文档导出逐项判断，不设一个总的“已连接”。
- **创作采用**：七集可交付不等于语感已获认可；用户确认之前不扩写剩余正文。
- **制作路径**：R7 需要具体执行人、条件和相应授权。拿不到反馈时只准备离线包，不阻断独立工程任务，也不宣称复工。

## 3. 每个任务的交接规则

任务表固定包含 ID、动作、前置任务、主责、修改／输入范围、实际产物、验收证据。阶段正文补充关键设计、非目标、正反用例与回退。任务实施时只需补本次修订、真实负责人、证据位置、结果和未决项，不重复抄写全部设计。

主责角色：E＝工作流工程；C＝创作方法；V＝独立复核；I＝集成；D＝导演／制片。一个人可以兼任，但不能把自己的复查写成独立验收。

任务状态用 `planned / in_progress / awaiting_evidence / verified / deferred`。设计文件存在不使任务变成 verified；有意推迟必须说明影响哪个发布路径。这里的任务状态不替代剧本、审查、人工决定或远端任务状态。

任一阶段交接必须包含：输入版本、当前产物、实际执行范围、未完成项、下一动作、回退方式。验收证据的责任人不等于必须额外增加一个 AI 代理；实际执行方式按能力和授权决定。

## 4. 工期与范围控制

沿用总方案的粗估：R0 1–2 日、R1 2–3 日、R2 4–6 日、R3 3–5 日、R4 3–4 日、R5 2–4 日、R6 3–4 日，共 18–28 个净工程工作日；R7 另估。52 个任务是可验收切片，不是新增 52 个开发日，也不要求 52 次用户审批。

R2 完成后用实际耗时重估剩余阶段。R4 评估运行量、人工阅读和模型费用须单列；无执行额度时保持待执行，不把未跑项目算通过。用户阅读和导演排期不包含在工程工期中。

本地核心逻辑验证为 R0–R4；完整本地交付还必须经过 R6，不能把核心代码可跑直接当作迁移和安装完成。

## 5. 本轮变更和下一动作

本轮只新增阶段文档并给总方案补入口，不修改运行代码、现有剧本、已安装技能、远端状态或任务。未创建 issue、工作树或调度，不进行付费验证。

获准实施后的第一组任务是 R0-01～R0-05；第一个可运行里程碑是 R2-08。后续执行人在开始前必须重新核对工作区，不能把本包记录的源码状态当成永久事实。
