# R6：迁移、七集试点与可回退发布

设计状态：已拆分待审；实现状态：planned。预计 3–4 个工程工作日，不含用户阅读与外部等待。对应 T10、T11 的本地交付部分。

## 1. 目标与入口

R2–R4 完成后，仍需证明旧项目能接入、安装不覆盖用户改动、换会话能恢复、回退不丢稿。联网能力仅在 R5 对应项通过时启用。

阶段输出是可使用、可回退的候选发行及私有七集交付；不是整季采用或制作放行。技术版发布、方法收益验证和本剧语感确认分别记录。

## 2. 旧项目导入

### 2.1 只读预览

用户明确项目根和输入集合；工具列出工作文件、历史快照、报告、决定证据、远端绑定及冲突。不递归收集无关目录，不把原剧、视频或凭据自动装入新流程。

文件名含 final、approved 或较新时间不能推定权威版本。没有审批原话或回执就保留 unknown。多份候选有冲突时展示映射候选，不自动合并正文。

预览返回来源摘要、拟登记清单与预览指纹。apply 必须核对预览未过期及 expectedRevision；源文件变化后重新预览。导入写入可选工作流目录，不改原正文或 PROJECT 手写说明。

### 2.2 影子运行到启用

先报告差异、失效和缺口，不自动修稿或强制升格历史数据。用已知正反例和一次实际接续观察误拦截；没有依据的历史“通过”不因此变可信。

启用仅改变本项目的工具入口和状态显示，不改变已有创作授权。影子模式同样不能输出假采用或假质量结论。

## 3. 安装与版本策略

复用现有 installer 的 owned receipt、文件摘要、修改检测、备份和验证。新增 bundle 文件必须被验证器和安装回执覆盖；方法版本、工具版本和 schemaVersion 分别记录，不能用一个 VERSION 证明全部兼容。

现有安装被用户修改时停止覆盖并展示冲突。旧版本不认识新 schema 时只读／拒绝写入，不能降级改写。项目资料、私人评估和回执始终不随技能分发。

回退分两层：技能回退恢复上一安装包；项目回退停用新机制并保留新产生的候选与记录。二者都不恢复用户旧正文来覆盖新改稿，不删除 `.drama` 或工作目录。

## 4. 七集私有试点

范围仍为 11–15、20–21，共七集。1–10 是保护基线；16–19、22 及必要后文只用于衔接；第二季和既定结局不因重构而改变。全部使用对应的实际文件版本，不把本次用户拆分任务当作扩稿授权。

先登记已有七集样段，验证来源、目标、报告和状态能恢复。若需要再次修改，必须有适用的具体修订授权；未改部分保持原候选身份，不能把七集样段包装为全季新版。

交付卡逐项回应：人物行为与声音、情绪过程、对抗与跨集因果。每项有新版位置、保留亮点、损失与未决项，用户直接读正文再给语感决定。任务可完成“交付待审”，但用户 pending 时不得扩全稿。

## 6. 验收与失败处置

演示至少覆盖：旧项目无 .drama；PROJECT 含用户手写段落；多份 final 稿；导入预览后正文被改；安装包被用户修改；新机制停用后旧工具仍能检查正文；七集和旧稿混合 edition 的身份可见。

R6-07 的联网启用是条件依赖：保存候选需要 R5-03/04，审查需要 R5-05，文档交付需要 R5-06；这些未验证不阻断纯本地发行，但必须关闭且说明。不能凭 R5-01 的工具发现启用所有功能。

独立复核者不能是同一改动的实现者却不披露；环境不支持时给自查证据并保留独立验收待办。若存在覆盖原稿、审批误升级、未知付费重复执行风险，本候选不得启用到真实项目。

迁移失败保留预览、未引用对象和原文件；不自动执行清理或 reset。安装失败使用已有恢复机制，恢复后重新 verify，不仅依赖“备份目录存在”。
